Run GROMACS on cpmdc forces¶

GROMACS can integrate on cpmdc energies and forces in process, for a QM group that is part of the system or all of it. libcpmdc_gromacs implements the libcp2k C API that GROMACS’ CP2K QM/MM interface calls, and answers each call with one cpmdc_session_calculate_au() of the C ABI. GROMACS links it in place of CP2K, so mdrun needs no extra process and no socket. Energies and forces need no change to GROMACS’ source; the QM virial, and so the pressure and NPT, needs a short patch to GROMACS’ QM/MM module (see Pressure and NPT).

Route

GROMACS side

Needs

libcpmdc_gromacs

the CP2K QM/MM interface, qmmm-cp2k-* mdp options

GROMACS 2024 or later built with -DGMX_DOUBLE=ON -DGMX_CP2K=ON against cpmdc’s libcp2k.pc

The GROMACS interface reference lists the input keys, units, cell, embedding, and virial conventions, and cpmdc inside MD engines explains why this route and reports runs on OpenCPMD.

The interface was checked with GROMACS 2024.6, 2025.5, and 2026.4; the three call the same libcp2k functions, and 2026 adds cp2k_get_positions and cp2k_get_version, which the library provides. The MPI build, the installed library, the OpenCPMD backend, and the virial patch were checked with 2025.5; the 2024.6 and 2026.4 patches apply and their QM/MM sources compile.

Build¶

Meson builds libcpmdc_gromacs.so with libcpmdc (-Dwith_gromacs_shim=auto, the default; it is off for the Python wheel build) and writes build/tools/gromacs/pkgconfig/libcp2k.pc, which points GROMACS at the library and at tools/gromacs/libcp2k.h. meson install puts the library in LIBDIR, the header in include/cpmdc/gromacs, and the .pc file in LIBDIR/cpmdc/gromacs/pkgconfig, apart from cpmdc’s own cpmdc.pc, so that libcp2k is found only where asked for.

GROMACS’ cmake/gmxManageCP2K.cmake requires CP2K_DIR, prepends CP2K_DIR/pkgconfig to PKG_CONFIG_PATH, and reads libcp2k.pc there, so pass the directory above pkgconfig. The patch line adds the QM virial; qmmm-virial-2024.patch is for 2024.6 and 2025.5, qmmm-virial-2026.patch for 2026.4. Without it GROMACS builds and runs NVE and NVT as before:

meson setup build && meson compile -C build
patch -p1 -d gromacs-2025.5 < tools/gromacs/patches/qmmm-virial-2024.patch
cmake -S gromacs-2025.5 -B build-gmx -G Ninja -DGMX_DOUBLE=ON -DGMX_MPI=OFF \
  -DGMX_CP2K=ON -DCP2K_DIR=$PWD/build/tools/gromacs
cmake --build build-gmx --target install

From an installed cpmdc:

meson setup build --prefix=$PWD/build/prefix && meson compile -C build
meson install -C build
cp2k_dir=$(dirname "$(dirname "$(find build/prefix -path '*/cpmdc/gromacs/pkgconfig/libcp2k.pc')")")
patch -p1 -d gromacs-2025.5 < tools/gromacs/patches/qmmm-virial-2024.patch
cmake -S gromacs-2025.5 -B build-gmx -G Ninja -DGMX_DOUBLE=ON -DGMX_MPI=OFF \
  -DGMX_CP2K=ON -DCP2K_DIR=$cp2k_dir

The installed libcp2k.pc gives -L, -Wl,-rpath and the two libraries in Libs, and -I for include/cpmdc/gromacs in Cflags, so any pkg-config consumer compiles, links and runs against it with no further flags. libcpmdc_gromacs records $ORIGIN on Linux and @loader_path on macOS, so it opens libcpmdc from its own directory after the prefix is moved. The installed library does not keep the build tree or the original prefix in RPATH or RUNPATH. GROMACS takes only the library names, directories, and include directories from it, not the -Wl,-rpath; it finds the library at run time because it records the directories it linked from as its run path (CMAKE_INSTALL_RPATH_USE_LINK_PATH). Either way libgromacs names the build tree or the prefix it was built against, and a GROMACS built against one does not follow the library to the other.

scripts/ci/build_gromacs_cpmdc.sh VERSION PREFIX CP2K_DIR [thread-mpi|mpi] downloads a pinned GROMACS release, checks its SHA-256, applies the virial patch for that release, builds it this way (mpi: -DGMX_MPI=ON with mpicc, mpicxx and mpifort from PATH), and checks that libgromacs resolves libcpmdc_gromacs to the libdir of that libcp2k.pc.

With OpenCPMD linked, GROMACS must use the BLAS and LAPACK libcpmdc links: GROMACS’ bundled ones (-DGMX_EXTERNAL_BLAS=OFF) export dgemm_ and the rest from libgromacs, OpenCPMD’s calls bind to them, and its nonlocal pseudopotential forces come out wrong (see Troubleshooting). The script passes -DGMX_EXTERNAL_BLAS=ON -DGMX_EXTERNAL_LAPACK=ON and the BLAS of libcpmdc when libcpmdc links one, and libcpmdc_gromacs stops mdrun when it finds dgemm_ in libgromacs with OpenCPMD linked.

Build GROMACS in double precision. Its QM/MM module stores cpmdc’s forces as real, which is float in a mixed-precision build, and the 1e-10 agreement below holds only for gmx_d.

Set up a run¶

The QM group is an index group. For GROMACS to generate its normal CP2K input, select the same functional, charge, and multiplicity as the CPMDParams message:

qmmm-cp2k-active      = true
qmmm-cp2k-qmgroup     = QM
qmmm-cp2k-qmmethod    = BLYP
qmmm-cp2k-qmcharge    = 0
qmmm-cp2k-qmmultiplicity = 1

Build the .tpr from the .mdp, then name the message when running it:

gmx_d grompp -f md.mdp -c conf.gro -p topol.top -n index.ndx -o md.tpr
CPMDC_GROMACS_PARAMS=water.params.bin \
  gmx_d mdrun -deffnm md -ntmpi 1

PBE works in place of BLYP when the deck’s effective functional is PBE. The library refuses a disagreement in the functional, charge, or multiplicity instead of replacing the deck value.

GROMACS writes zero, not the original topology charge, for every QM atom in its generated PDB. A generated run with charged MM atoms therefore cannot obtain the QM_CHARGES needed for mechanical embedding and is refused. Use the explicit route below for that case.

The explicit route sets qmmm-cp2k-qmmethod = INPUT and makes grompp take the cpmdc settings from the file of -qmi:

qmmm-cp2k-active      = true
qmmm-cp2k-qmgroup     = QM
qmmm-cp2k-qmmethod    = INPUT
qmmm-cp2k-qmcharge    = 0
qmmm-cp2k-qmmultiplicity = 1

cpmdc.gromacs.write_qmi() writes that file; qmi_input() returns its text:

from cpmdc.gromacs import write_qmi

write_qmi("cpmdc.inp", "water.params.bin", embedding="MECHANICAL",
          qm_charges=[-0.834, 0.417, 0.417])

gmx_d grompp -f md.mdp -c conf.gro -p topol.top -n index.ndx -qmi cpmdc.inp -o md.tpr
gmx_d mdrun -deffnm md -ntmpi 1

The CHARGE and MULTIPLICITY that write_qmi() writes in &DFT (or the first CHARGE and MULTIPLICITY anywhere in a hand-written -qmi input, which GROMACS reads for the QM charge) must equal the charge and multiplicity of the CPMDParams message: pass charge= and multiplicity= to write_qmi() for a deck that is not neutral and singlet, and mdrun stops with both values when they differ. A CHARGE line added above &DFT, even inside &CPMDC, is the one GROMACS and the library read. The file of -qmi holds a &CPMDC section inside &FORCE_EVAL: PARAMS names the CPMDParams message, CELL and EMBEDDING choose the cell and the QM-MM Coulomb term, QM_CHARGES gives the QM atoms’ classical charges, EPSILON_R scales the mechanical-embedding QM-MM Coulomb term when .mdp sets epsilon-r other than 1 (because GROMACS’ CP2K module does not forward epsilon-r to libcp2k), and QM_RANKS sets the ranks of an MPI GROMACS. The reference lists every key and what the library writes to md_cp2k.out. An explicit &CPMDC section takes precedence over CPMDC_GROMACS_PARAMS.

Cap a bond across the QM boundary¶

A QM group that cuts a covalent bond needs no extra step with the generated input: grompp finds each bond between a QM atom and an MM atom and writes a &LINK section for it, and the library caps the bond with a hydrogen in the QM calculation. The CPMDParams message describes the QM atoms only; the hydrogens are added to them for you, so their number does not appear in the deck. The input CHARGE and MULTIPLICITY (placed in &DFT by write_qmi()) stay the charge and multiplicity of that message when a bond is capped. The hydrogen is not counted into either value. md_cp2k.out reports links N on its line of atom counts.

With qmmm-cp2k-qmmethod = INPUT name each bond beside &CPMDC, by the 1-based atom numbers of the GROMACS system, QM atom first:

from cpmdc.gromacs import write_qmi

# atom 1 (QM) is bonded to atom 4 (MM)
write_qmi("cpmdc.inp", "water.params.bin", embedding="NONE", links=[(1, 4)])

link_alpha sets ALPHA_IMOMM; the library default is CP2K’s 1.38. Choose it as the ratio of the equilibrium QM-MM bond length to the QM-H bond length of the method.

The MM atom gets its share of the force on the hydrogen, so GROMACS integrates it as it does any other atom. With EMBEDDING MECHANICAL the charge of the MM atom of each cut bond leaves the QM-MM Coulomb sum; see the reference for the hydrogen position, the force shares, the virial, and what is not implemented.

Pressure and NPT¶

NPT works with a GROMACS patched as in Build. The QM virial is the full tensor, in a cubic or triclinic box, so C-rescale, Parrinello-Rahman, and the other barostats see the QM part of the pressure whatever coupling type they use; the runs in the OpenCPMD runs use isotropic C-rescale and Parrinello-Rahman.

An unpatched GROMACS reports a pressure without the QM and QM-MM terms. The reference gives the virial the library returns in each cell mode, and when it reports none.

An NPT mdp adds the barostat to the QM/MM settings above, for example:

integrator       = md
tcoupl           = v-rescale
tc-grps          = System
tau-t            = 0.1
ref-t            = 300
pcoupl           = C-rescale
pcoupltype       = isotropic
tau-p            = 0.5
ref-p            = 1.0
compressibility  = 4.5e-5

Two cautions:

  • with CELL PERIODIC, each new box is a new setup of the deck at its cutoff, so the plane-wave basis changes with the box. OpenCPMD’s stress is the derivative at a fixed basis and carries the Pulay stress of that cutoff, so set constantCutoff = [A, sigma, E0] in the system section of the message for a periodic NPT run, as relax a cell at a constant cutoff shows;

  • with CELL NONE the deck’s cell has to hold the QM region and its density, not the region’s path: cpmdc centres the region in it on each step.

Several ranks¶

A thread-MPI GROMACS runs QM/MM on one rank: pass -ntmpi 1, because GROMACS refuses more thread-MPI ranks with QM/MM.

For more ranks, build GROMACS with -DGMX_MPI=ON against the MPI that libcpmdc_gromacs links (scripts/ci/build_gromacs_cpmdc.sh with mpi), and do not ask for separate PME ranks, which GROMACS refuses with QM/MM. Then choose QM_RANKS in &CPMDC:

  • QM_RANKS ALL, the default, runs one cpmdc calculator on every rank of mdrun; with OpenCPMD the forces differ from a one-rank run by the order of its parallel sums;

  • QM_RANKS 1 runs the QM calculation on rank 0 alone and matches a one-rank run to 1e-10, at the SCF time of one rank.

A libcpmdc_gromacs built without MPI stops mdrun on an MPI GROMACS with the reason. The reference describes how the library shares each step across the ranks.
