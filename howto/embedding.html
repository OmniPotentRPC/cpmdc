Embedding cpmdc¶

Goal¶

Call libcpmdc from a host program: pick an entry point, send the method message and one geometry message per step, step a session, read the result, and keep orbitals, RESTART files, and MPI ranks consistent between steps. This page names the call for each task. The C ABI reference states what each call promises (arguments, return codes, size rules, units), and API contracts adds ownership, thread and MPI behaviour, errors, and defaults.

Use the session result path for new drivers. It keeps method setup and topology state in one object while preserving the same PotentialResult carrier used by RPC frontends, cross-language bindings, and drivers that already use the shared OmniPotentRPC schema. The compatibility array calls suit a host that already owns native C arrays and only needs Hartree and Hartree/Bohr values.

Molecular dynamics engines with their own integrator and units usually want cpmdc_session_calculate_au(): one copy of the positions in, the forces and the virial out. tools/lammps/pair_cpmdc.cpp, the LAMMPS pair_style cpmdc, is a complete host on it, with unit conversion, the triclinic cell, and the MPI gather to one rank; Run LAMMPS on cpmdc forces documents it beside the Python fix external route. tools/gromacs/cpmdc_gromacs.c is a host on the same call behind another program’s C API, libcp2k, with electrostatic and mechanical QM-MM embedding; see Run GROMACS on cpmdc forces.

Arguments, units, and return conventions of each row are in the C ABI conventions and the section for its call family (global array calls, sessions, one-shot calls, discovery).

Check what the build supports¶

cpmdc.h also exposes a small feature table. Inspect it before building inputs, hiding unsupported controls, or deciding whether a stub build is sufficient for a workflow.

size_t feature_count = cpmdc_feature_count();
const CPMDCFeatureEntry *features = cpmdc_feature_table();
const CPMDCFeatureEntry *pimd =
    cpmdc_feature_find("catalog.section.PIMD");
const CPMDCFeatureEntry *result_call =
    cpmdc_feature_find("abi.cpmdc_session_calculate_result");

if (pimd != NULL && pimd->embed_applicable) {
  /* The embedded OpenCPMD build can render a &PIMD section. */
}

The entry layout says which builds expose a feature. The CPMD option mapping lists the ID namespaces (catalog.section.*, catalog.cpmd.*, catalog.dft.*, params.*, abi.*) and the params.inputSections.<section>.<field> field IDs; the feature inventory describes the table.

Send the message¶

There are two wire messages in a normal embedded driver:

Message

Lifetime

Contents

CPMDParams

Session setup

method, structured CPMD sections, pseudopotentials, engine hints

ForceInput

One calculation step

positions, atomic numbers, optional cell, requested output units

Wire structs are generated from schema/Potentials.capnp; the header does not redefine CPMDParams fields as a second C struct language. CPMDParams owns method and backend setup. ForceInput owns coordinates, atomic numbers, unit strings, and the optional 3 by 3 cell for a single evaluation. The runtime renders a CPMD INPUT deck from CPMDParams and merges the step geometry into it on each cold evaluation.

Build CPMDParams once and serialize it as an unpacked flat Cap’n Proto message; Writing a CPMDParams message shows how to write one by hand. Build one ForceInput per geometry step. The PotentialResult path converts the output to ForceInput.energyUnit and ForceInput.energyUnit / ForceInput.lengthUnit. The C ABI conventions state the buffer format, the ForceInput unit strings, and the box rules.

When the host owns arrays in Angstrom and wants Hartree or Hartree/Bohr output directly, the scalar calls take the arrays and the CPMDParams bytes:

#include <cpmdc.h>
#include <stdlib.h>

int rc = cpmdc_set_params(params_bytes, params_size);
CPMDCResult result = cpmdc_energy_gradient(
    n_atoms, positions_ang, atomic_numbers, params_bytes, params_size,
    gradient_h_bohr);
CPMDCResult forces = cpmdc_energy_forces(
    n_atoms, positions_ang, atomic_numbers, params_bytes, params_size,
    forces_h_bohr);

The reference covers these under global array calls and session array steps.

Step a session¶

Callers that drive multiple geometry steps keep method state in a session and pass a serialized ForceInput for each step. The result-carrier entry point writes an unpacked flat PotentialResult for RPC-style or in-process loops.

CPMDCSession *session = cpmdc_session_create(params_bytes, params_size);

if (session != NULL) {
  size_t forces_len = n_atoms * 3;
  double *forces_h_bohr = calloc(forces_len, sizeof(*forces_h_bohr));
  size_t potential_result_capacity =
      cpmdc_potential_result_size_for_force_input(
          force_input_bytes, force_input_size);
  unsigned char *potential_result_bytes =
      malloc(potential_result_capacity);
  size_t potential_result_size = 0;

  CPMDCResult step = cpmdc_session_calculate_forces(
      session, force_input_bytes, force_input_size, forces_h_bohr,
      forces_len);

  CPMDCResult rpc_step = cpmdc_session_calculate_result(
      session, force_input_bytes, force_input_size,
      potential_result_bytes, potential_result_capacity,
      &potential_result_size);

  free(forces_h_bohr);
  free(potential_result_bytes);
  cpmdc_session_destroy(session);
}

Use the session path for optimizers, molecular dynamics drivers, and RPC frontends. It avoids reparsing method setup on every step and gives the runtime one place to enforce topology consistency.

Three habits keep a host loop correct:

  • Size the PotentialResult buffer with cpmdc_potential_result_size_for_force_input() before each serialized call, as above; session message steps say what a zero size and a short buffer mean.

  • Free the CPMDParams bytes after creating the session; the session keeps its own copy (the session type).

  • Create a new CPMDCSession to change the atom count, the elemental composition, or the method once an evaluation has been accepted (sessions say when the topology is fixed).

Read the energy terms of the last evaluation in Hartree with cpmdc_last_energy_components() instead of parsing CLI ENERGY files; see results of the last evaluation.

For a complete host-side skeleton, see examples/host_step.c. The checked example-host-step Meson test runs that program with generated fixture bytes and expects output shaped like:

energy_h=...
potential_result_size_bytes=...
message=...

Handle status and errors¶

Check every call before using its outputs. A call that returns CPMDCResult reports success in ok and carries the status or error text in message. A session helper that returns int, such as cpmdc_session_calculate_au(), cpmdc_session_select_orbitals(), or cpmdc_session_copy_orbitals(), returns 0 or -1 and puts the reason in cpmdc_last_error() instead of filling CPMDCResult. The C ABI conventions list the return convention of each call, and library status lists which calls write cpmdc_last_error() and how it behaves.

To find the cause of a failure, read message or cpmdc_last_error(), then look the text up in Troubleshooting, which lists common message values. From Python the same failures arrive as CPMDCError, cpmdc.ipi.ProtocolError on the i-PI driver, and ASE’s CalculationFailed; see the Python reference.

Keep orbitals between steps¶

OpenCPMD keeps one set of converged orbitals for the whole process, not inside a CPMDCSession, and starts the next step from it when the functional, deck, cutoff, cell, charge, multiplicity, atom count, and elemental composition match. A change to any of these is a cold start, and so is the first step of the process. A session refuses a new atom count or composition, so those change only with a new session, and a new session whose values match starts warm. A constant-cutoff deck under CPMDC_CELL_IN_PLACE may also move the cell without a cold start. Wavefunction state between calls explains warm starts, extrapolation, and when a step restarts from atomic orbitals.

To run several trajectories on one session, name an orbital store with cpmdc_session_select_orbitals() and duplicate one with cpmdc_session_copy_orbitals(); see extrapolate the orbitals for the workflow and the session section of the reference for the calls. CPMDC_ORBITAL_SLOT_LIMIT caps parked orbital copies plus populated extrapolation-history entries, including the selected key’s entries, on an OpenCPMD build; the reference build counts parked keys only. A new park past the cap fails without discarding the ones already stored; see environment variables.

Choose a CPMDParams carrier¶

Structured inputSections should be preferred over raw blocks when a typed arm exists:

  • system for cells, cutoff/grid/mesh controls, state occupation, external fields, CDFT (constrained DFT) Gaussian controls, pressure and stress controls, Poisson settings, isolated-shape controls, charge, and spin multiplicity

  • cpmd for wavefunction optimization, MD, convergence, restart, and trajectory controls

  • dft for functional and spin-polarized DFT controls

  • atoms for pseudopotential grouping and fixed non-coordinate &ATOMS directives

  • named OpenCPMD section arms such as pimd, vdw, linres, and tddft for keyword/value lines and nested subsection blocks

Use generic for non-catalog aliases, set for merge-only keywords inside a named section, and raw or inputBlocks for text-preserving deck fragments. Choose the least lossy structured carrier:

On a geometry render that is not the OpenCPMD merge, typed atoms sections must cover every element present in the step, and a missing atoms section covers H and O only (CPMD option mapping). On the OpenCPMD path the &ATOMS block is rebuilt from each step: elements in atoms.pseudopotentials supply the file, LMAX, LOC, and KLEINMAN-BYLANDER, elements the message omits use the built-in table for H, C, N, O, Si, and Ge, and an element in neither is an error (writing a CPMDParams message).

Keep the wavefunction from a RESTART file¶

The binary RESTART file is a separate object from the deck keyword. Read and rewrite it with cpmdc-restart or cpmdc_restart.h (libcpmdc_restart). To keep orbitals while the host owns the next geometry:

  1. Read the file with cpmdc_restart_read_path() or cpmdc_restart_read_mem().

  2. Replace the positions with cpmdc_restart_set_coordinates().

  3. Write the file back with cpmdc_restart_write_path() or cpmdc_restart_write_mem().

Coordinates in that file are Bohr in species order. A coordinate patch copies the wavefunction records unchanged, which is how a host keeps orbitals while it owns the next geometry. The RESTART file library section of the reference gives every call’s contract.

Put RESTART WAVEFUNCTION in the deck to start a cold SCF from the patched file; the OpenCPMD path ignores restarted coordinates, velocities, and geometry, because each step supplies them.

Adopt an MPI communicator¶

When a host already split MPI_COMM_WORLD into calculator groups, call cpmdc_adopt_calculator_comm() before the first session evaluates, instead of cpmdc_bind_calculator(). The call borrows the communicator: keep it alive until the last session is destroyed or a later adopt replaces it. The rules and a sketch are in Run under mpirun, and the contracts of both calls are under MPI in the C ABI reference.

The optional plane-wave scaffold in include/cpmdc_pwscale.h times FFT and MPI paths separately from production libcpmdc; see Plane-wave scaffold reference and Time plane-wave scaling across ranks. cpmdc_pwscale_eval_cuda() runs the CUDA kernel when the build uses -Dwith_pwscale_cuda=true.

Set the OpenCPMD runtime inputs¶

Archive builds require -Dwith_cpmd=true and -Dcpmd_root=/path/to/OpenCPMD. That tree must contain lib/libcpmd.a and the OpenCPMD object/include files from a completed executable build with the patches in tools/; see building the archive.

Set CPMDC_PSEUDO_DIR to the directory holding the pseudopotential files. A cold evaluation changes into that directory while CPMD reads them (ratom and recpnew), then returns to the host’s directory. CPMD_PP_LIBRARY_PATH is the fallback when CPMDC_PSEUDO_DIR is unset; with neither set, a cold evaluation fails. Environment variables name CPMDC_PSEUDO_DIR and the embed flags CPMDC_STRESS, CPMDC_WARM_RMSD, and the rest.

CPMDC_DECK_OUT names a file that receives the method deck cpmdc renders from CPMDParams; see debugging a deck for what the OpenCPMD path adds before CPMD parses it.

On a cold OpenCPMD evaluation the Fortran bridge in src/cpmd_embed_c_api.F90 composes the full deck, and src/cpmdc_memfd.c puts it in an anonymous Linux memfd_create file that CPMD reads as /proc/self/fd/N, so no INPUT file reaches the disk. A failure while composing that deck, creating the memfd, or entering the pseudopotential directory is agreed by every calculator rank before OpenCPMD setup begins, and every rank reports the same text. A deck that already defines an external potential is one of those failures. A warm step whose output directory is not a directory is agreed before the energy evaluation, and that setup stays in place. src/cpmdc_embed_host.c resolves the pseudopotential directory and maps species-block gradients back to atom order. Architecture walks the layer list.

Drive cpmdc through rgpot or a socket¶

rgpot loads libcpmdc.so in CPMDPot, maps host coordinates into ForceInput, and reads a serialized PotentialResult from cpmdc_session_calculate_result(). CPMDC_LIBRARY, RGPOT_CPMDC_ENGINE, and RGPOT_CPMD_ENGINE name the library path; see environment variables and eOn through rgpot for a full minimisation.

Drive cpmdc over the i-PI socket protocol documents cpmdc-ipi, which holds one Python Session, and cpmdc-ipi-c, which holds one CPMDCSession * and calls cpmdc_session_calculate_au() with Bohr arrays and the virial output. Each evaluates when the server’s POSDATA message arrives and sends the stored result when GETFORCE asks for it. The page also names the C ABI call that cpmdc-ipi makes for each step.

Check forces from a live link¶

Nuclear forces from repeated SCF calls explains how a live OpenCPMD link exports forces and what makes a call warm. Check forces and stress by finite differences compares the forces of a session with central differences of its energy.

Prefer an off-equilibrium water or similar system when checking forces. Some tightly packed cluster geometries can report a zero nuclear gradient even under native cpmd.x; an energy that changes between calls does not show that the forces are right.

Example environment for a live driver:

export CPMDC_LIBRARY=/path/to/libcpmdc.so
export CPMDC_PSEUDO_DIR=/path/to/pseudopotentials
# one session, many ForceInput steps via cpmdc_session_calculate_forces
