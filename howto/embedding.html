Embedding cpmdc¶

Molecular dynamics engines with their own integrator and units usually want cpmdc_session_calculate_au: one copy of the positions in, the forces and the virial out. tools/lammps/pair_cpmdc.cpp, the LAMMPS pair_style cpmdc, is a complete host on it, with unit conversion, the triclinic cell, and the MPI gather to one rank; Run LAMMPS on cpmdc forces documents it beside the Python fix external route. tools/gromacs/cpmdc_gromacs.c is a host on the same call behind another program’s C API, libcp2k, with mechanical QM-MM embedding; see Run GROMACS on cpmdc forces.

Use the session result path for new drivers. It keeps method setup and topology state in one object while preserving the same PotentialResult carrier used by RPC frontends.

The compatibility array calls are useful when a host already owns native C arrays and only needs Hartree/Hartree-per-Bohr values. The serialized result calls are the better boundary for RPC frontends, cross-language bindings, and drivers that already use the shared OmniPotentRPC schema.

C ABI¶

Include cpmdc.h and pass serialized Cap’n Proto message bytes to the ABI functions. Wire structs are generated from schema/Potentials.capnp; the header does not redefine CPMDParams fields as a second C struct language.

#include <cpmdc.h>
#include <stdlib.h>

int rc = cpmdc_set_params(params_bytes, params_size);
CPMDCResult result = cpmdc_energy_gradient(
    n_atoms, positions_ang, atomic_numbers, params_bytes, params_size,
    gradient_h_bohr);
CPMDCResult forces = cpmdc_energy_forces(
    n_atoms, positions_ang, atomic_numbers, params_bytes, params_size,
    forces_h_bohr);

params_bytes is an unpacked flat Cap’n Proto message whose root is CPMDParams. It can come from pycapnp, a memory-mapped file, rgpot, or another Cap’n Proto binding that writes the standard flat stream format. Use the scalar calls when the caller already owns arrays in Angstrom and wants Hartree or Hartree/Bohr output directly.

For a complete host-side skeleton, see examples/host_step.c. The checked example-host-step Meson test runs that program with generated fixture bytes and expects output shaped like:

energy_h=...
potential_result_size_bytes=...
message=...

Message Flow¶

There are two wire messages in a normal embedded driver:

Message

Lifetime

Contents

CPMDParams

Session setup

method, structured CPMD sections, pseudopotentials, engine hints

ForceInput

One calculation step

positions, atomic numbers, optional cell, requested output units

A host should build CPMDParams once, serialize it as an unpacked flat Cap’n Proto message, and create a CPMDCSession. Each geometry step is a separate ForceInput message passed to cpmdc_session_calculate_result() or the lower-level force calls. The PotentialResult path converts output to ForceInput.energyUnit and ForceInput.energyUnit / ForceInput.lengthUnit.

Feature Discovery¶

cpmdc.h also exposes a small feature table. Embedders can inspect it before building inputs, hiding unsupported controls, or deciding whether a stub build is sufficient for a workflow.

size_t feature_count = cpmdc_feature_count();
const CPMDCFeatureEntry *features = cpmdc_feature_table();
const CPMDCFeatureEntry *pimd =
    cpmdc_feature_find("catalog.section.PIMD");
const CPMDCFeatureEntry *result_call =
    cpmdc_feature_find("abi.cpmdc_session_calculate_result");

if (pimd != NULL && pimd->embed_applicable) {
  /* The embedded OpenCPMD build can render a &PIMD section. */
}

Feature IDs use namespaces such as catalog.section.*, catalog.cpmd.*, catalog.dft.*, params.*, and abi.*. Each entry reports whether it applies to stub builds, embedded OpenCPMD builds, or both. Structured field controls are discoverable with params.inputSections.<section>.<field> IDs, for example params.inputSections.cpmd.maxIter, params.inputSections.dft.hfxScreening, and params.inputSections.atoms.pseudopotentials.

Session Step Calls (direct-call socket)¶

Callers that drive multiple geometry steps keep method state in a session and pass a serialized ForceInput for each step. The result-carrier entry point writes an unpacked flat PotentialResult for RPC-style or in-process loops.

CPMDCSession *session = cpmdc_session_create(params_bytes, params_size);

if (session != NULL) {
  size_t forces_len = n_atoms * 3;
  double *forces_h_bohr = calloc(forces_len, sizeof(*forces_h_bohr));
  size_t potential_result_capacity =
      cpmdc_potential_result_size_for_force_input(
          force_input_bytes, force_input_size);
  unsigned char *potential_result_bytes =
      malloc(potential_result_capacity);
  size_t potential_result_size = 0;

  CPMDCResult step = cpmdc_session_calculate_forces(
      session, force_input_bytes, force_input_size, forces_h_bohr,
      forces_len);

  CPMDCResult rpc_step = cpmdc_session_calculate_result(
      session, force_input_bytes, force_input_size,
      potential_result_bytes, potential_result_capacity,
      &potential_result_size);

  free(forces_h_bohr);
  free(potential_result_bytes);
  cpmdc_session_destroy(session);
}

When potential_result_capacity is too small, ok == 0, the required byte count is written to potential_result_size, and OpenCPMD is not evaluated, the same contract as the session result call of the NWChem library nwchemc.

Use the session path for optimizers, molecular dynamics drivers, and RPC frontends. It avoids reparsing method setup on every step and gives the runtime one place to enforce topology consistency.

Rules a host follows¶

The C ABI reference states each call’s contract; these are the ones that shape a host loop:

  • Size the PotentialResult buffer with cpmdc_potential_result_size_for_force_input() before each serialized call, as in the example above. A return of 0 means the ForceInput is invalid; a short buffer gives ok == 0 with the needed size in potential_result_size.

  • cpmdc_session_create() copies the CPMDParams bytes, so the caller may free them at once.

  • session_accept_topology fixes the topology only after an evaluation call passes its argument checks and collective orbital preflight. A rejected preflight leaves the topology configurable. Change the atom count, the elemental composition, or the method after that call, by creating a new CPMDCSession; cpmdc_session_set_params() only works before it.

  • The native array calls take Angstrom and return Hartree and Hartree/Bohr; cpmdc_session_calculate_au() takes Bohr. PotentialResult values use the units the ForceInput names (for example eV and eV/angstrom).

  • cpmdc_last_energy_components() reads the energy terms of the last evaluation in Hartree, without parsing CLI ENERGY files.

Status and errors¶

Calls that return CPMDCResult set ok, Hartree energy_h, and a null-terminated message on success or failure. Session helpers that return int, including cpmdc_session_calculate_au(), cpmdc_session_select_orbitals(), and cpmdc_session_copy_orbitals(), use 0 on success and -1 on failure; they write cpmdc_last_error() instead of filling CPMDCResult. cpmdc_last_error() matches message when the call returns CPMDCResult; the C ABI reference lists which signature each call uses. It is per-thread, empty after a success, and is not written by the snapshot getters (cpmdc_last_stress() and the rest). Troubleshooting lists common message values. The Python reference maps the same failures to CPMDCError, cpmdc.ipi.ProtocolError on the i-PI driver, and ASE’s CalculationFailed.

Orbitals between steps¶

OpenCPMD keeps one set of converged orbitals for the whole process, not inside a CPMDCSession, and starts the next step from it when the functional, deck, cutoff, cell, charge, multiplicity, atom count, and elemental composition match. A change to any of these is a cold start, and so is the first step of the process. A session refuses a new atom count or composition, so those change only with a new session, and a new session whose values match starts warm. A constant-cutoff deck under CPMDC_CELL_IN_PLACE may also move the cell without a cold start. Wavefunction state between calls explains warm starts, extrapolation, and when a step restarts from atomic orbitals. cpmdc_session_select_orbitals() and cpmdc_session_copy_orbitals() name orbital stores by integer keys when a host runs several trajectories on one session; see extrapolate the orbitals. CPMDC_ORBITAL_SLOT_LIMIT caps how many of those copies stay parked, and a new park past the cap fails without discarding the ones already stored.

rgpot CPMDPot¶

rgpot loads libcpmdc.so in CPMDPot, maps host coordinates into ForceInput, and reads a serialized PotentialResult from cpmdc_session_calculate_result(). CPMDC_LIBRARY, RGPOT_CPMDC_ENGINE, and RGPOT_CPMD_ENGINE name the library path; see environment variables and eOn through rgpot for a full minimisation.

Socket and in-process drivers¶

Drive cpmdc over the i-PI socket protocol documents cpmdc-ipi and cpmdc-ipi-c. cpmdc-ipi holds one Python Session and cpmdc-ipi-c holds one CPMDCSession *. Each evaluates when the server’s POSDATA message arrives and sends the stored result when GETFORCE asks for it. cpmdc-ipi evaluates through Session.energy_forces() in python/cpmdc/ipi.py, which calls cpmdc_session_energy_forces() without a cell or cpmdc_session_calculate_forces() when the step sends a cell that is not all zero and --cluster is not set. cpmdc-ipi-c in tools/cpmdc_ipi.c calls cpmdc_session_calculate_au() directly with Bohr arrays and the virial output.

CPMD Input Ownership¶

CPMDParams owns method and backend setup. ForceInput owns coordinates, atomic numbers, unit strings, and the optional 3 by 3 cell for a single evaluation. The runtime renders a CPMD INPUT deck from CPMDParams and merges the step geometry into it on each cold evaluation.

Structured inputSections should be preferred over raw blocks when a typed arm exists:

  • system for cells, cutoff/grid/mesh controls, state occupation, external fields, CDFT (constrained DFT) Gaussian controls, pressure and stress controls, Poisson settings, isolated-shape controls, charge, and spin multiplicity

  • cpmd for wavefunction optimization, MD, convergence, restart, and trajectory controls

  • dft for functional and spin-polarized DFT controls

  • atoms for pseudopotential grouping and fixed non-coordinate &ATOMS directives

  • named OpenCPMD section arms such as pimd, vdw, linres, and tddft for keyword/value lines and nested subsection blocks

Use generic for non-catalog aliases, set for merge-only keywords inside a named section, and raw or inputBlocks for text-preserving deck fragments. On a geometry render that is not the OpenCPMD merge, typed atoms sections must cover every element present in the step, and a missing atoms section covers H and O only. On the OpenCPMD path the &ATOMS block CPMD reads is rebuilt from each step. Elements listed in atoms.pseudopotentials supply the file, LMAX, LOC, and KLEINMAN-BYLANDER on the \*file line. Elements the message omits use the built-in table for H, C, N, O, Si, and Ge. An element in neither is an error. See writing a CPMDParams message.

RESTART files¶

The binary RESTART file is a separate object from the deck keyword. Read and rewrite it with cpmdc-restart or cpmdc_restart.h (libcpmdc_restart). Coordinates in that file are Bohr in species order. A coordinate patch copies the wavefunction records unchanged, which is how a host keeps orbitals while it owns the next geometry. Put RESTART WAVEFUNCTION in the deck to start a cold SCF from the patched file; the OpenCPMD path ignores restarted coordinates, velocities, and geometry, because each step supplies them.

In-process cold deck and memfd¶

On a cold OpenCPMD evaluation the Fortran bridge in src/cpmd_embed_c_api.F90 composes the full deck, then src/cpmdc_memfd.c writes it into an anonymous Linux memfd_create file and exposes it to CPMD as /proc/self/fd/N so the parsers see a path without writing INPUT to disk. src/cpmdc_embed_host.c switches the working directory for pseudopotential reads and output, maps species-block gradients back to atom order, and records embed failures for the C result path. Architecture walks the layer list; Environment variables name CPMDC_PSEUDO_DIR and the embed flags CPMDC_STRESS, CPMDC_WARM_RMSD, and the rest.

MPI adoption and plane-wave scaling¶

When a host already split MPI_COMM_WORLD into calculator groups, call cpmdc_adopt_calculator_comm() before the first session instead of cpmdc_bind_calculator(). The rules and a sketch are in Run under mpirun. The optional plane-wave scaffold in include/cpmdc_pwscale.h times FFT and MPI paths separately from production libcpmdc; see Plane-wave scaffold reference and Time plane-wave scaling across ranks. cpmdc_pwscale_eval_cuda() runs the CUDA kernel when the build uses -Dwith_pwscale_cuda=true.

OpenCPMD Runtime Inputs¶

Archive builds require -Dwith_cpmd=true and -Dcpmd_root=/path/to/OpenCPMD. That tree must contain lib/libcpmd.a and the OpenCPMD object/include files from a completed executable build with the patches in tools/; see building the archive.

Set CPMDC_PSEUDO_DIR to the directory holding the pseudopotential files. A cold evaluation changes into that directory while CPMD reads them (ratom and recpnew), then returns to the host’s directory. CPMD_PP_LIBRARY_PATH is the fallback when CPMDC_PSEUDO_DIR is unset; with neither set, a cold evaluation fails.

CPMDC_DECK_OUT names a file that receives the method deck cpmdc renders from CPMDParams; see debugging a deck for what the OpenCPMD path adds before CPMD parses it.

Check forces from a live link¶

Nuclear forces from repeated SCF calls explains how a live OpenCPMD link exports forces and what makes a call warm.

Prefer an off-equilibrium water or similar system when checking forces. Some tightly packed cluster geometries can report a zero nuclear gradient even under native cpmd.x; an energy that changes between calls does not show that the forces are right.

Example environment for a live driver:

export CPMDC_LIBRARY=/path/to/libcpmdc.so
export CPMDC_PSEUDO_DIR=/path/to/pseudopotentials
# one session, many ForceInput steps via cpmdc_session_calculate_forces
