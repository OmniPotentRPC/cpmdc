Install and build¶

What gets built¶

A cpmdc build produces the shared libraries libcpmdc.so and libcpmdc_csvr, and a few helpers around them. Outside a with_python build, libcpmdc_csvr records SONAME libcpmdc_csvr.so.0. The build has two modes, selected by the Meson option with_cpmd:

Mode

Option

Evaluator behind the C ABI

cpmdc_available()

Default

-Dwith_cpmd=false

deterministic reference evaluator, no OpenCPMD

0

OpenCPMD

-Dwith_cpmd=true -Dcpmd_root=DIR

OpenCPMD linked from DIR/lib/libcpmd.a

1

Both modes export the same symbols. A third target, libcpmdc_stub.a, is a link-only placeholder: every call fails and cpmdc_available() returns 0. The tests use it to check the ABI without a working evaluator.

The optional tools (cpmdc-ipi-c, the LAMMPS plugin, and libcpmdc_gromacs) are listed with the options that build them in the build reference.

MAJOR is the soversion, the first field of version.txt. A with_python build sets no soversion, because a wheel stores no symlinks. libcpmdc_csvr keeps its own soversion, 0, so a later change of the generator layout can bump it without following that major. A with_python build leaves that library unversioned for the same reason.

meson subprojects download

Build the default library¶

Clone the repository and run the default suite:

git clone https://github.com/OmniPotentRPC/cpmdc.git
cd cpmdc
pixi run test-stub

test-stub configures build/ with tests on, compiles, and runs the Meson suite. A healthy run reports no failures. The same steps without Pixi:

meson setup build -Dwith_tests=true
meson compile -C build
meson test -C build --print-errorlogs

The build reference lists every Meson option, installed artifact, and Pixi task.

Build against OpenCPMD¶

The OpenCPMD archive needs the patches in tools/ and position-independent code; the archive how-to covers that build. With the archive in place:

export CPMD_ROOT=/path/to/opencpmd-build
meson setup build-cpmd \
  -Dwith_cpmd=true \
  -Dcpmd_root="$CPMD_ROOT" \
  -Dwith_tests=true
meson compile -C build-cpmd
export CPMDC_PSEUDO_DIR=/path/to/PP_LIBRARY
meson test -C build-cpmd --print-errorlogs

Configuration stops when $CPMD_ROOT/lib/libcpmd.a or $CPMD_ROOT/obj/timetag.o is missing. The live tests run OpenCPMD, which reads the pseudopotentials from CPMDC_PSEUDO_DIR (see the environment reference).

The link uses the MPI Fortran dependency, OpenBLAS (or LAPACK and BLAS when OpenBLAS is absent), FFTW3 when found, libgfortran, and libquadmath. When OpenCPMD was built with MPI compiler wrappers, configure with the same wrappers so both sides agree on one MPI:

CC=mpicc FC=mpif90 meson setup build-cpmd \
  -Dwith_cpmd=true -Dcpmd_root="$CPMD_ROOT"

Install¶

meson setup build-install --prefix "$HOME/.local" -Dwith_tests=false
meson install -C build-install
pkg-config --modversion cpmdc

The last command prints the project version, which Meson reads from version.txt. Hosts that load the library at run time, such as rgpot, look for it through CPMDC_LIBRARY; see the environment reference.

Installed shared libraries and plugins that need another library from the prefix record a run path relative to their own file: $ORIGIN on Linux and @loader_path on macOS. libcpmdc sets an empty install run path, because it does not load another library from the prefix; toolchain directories Meson already recorded, such as the one for libgfortran, stay. libcpmdc_gromacs records $ORIGIN (its own directory). The LAMMPS plugin is installed one directory deeper, in lib/cpmdc, and records $ORIGIN/... cpmdc-ipi-c records the normalised relative path from the resolved bindir to the resolved libdir. -Dbindir=., absolute bindir and libdir under the prefix, a nested libdir, and a path that contains .. or a trailing slash still open libcpmdc. A layout whose relative path cannot be stored as one run path entry fails at configure time. Meson keeps a build-tree run path only on uninstalled binaries. After meson install, an installed .so or .dylib does not point at the build tree or at the prefix path used for that install, so the tree can be moved and libcpmdc_gromacs still opens libcpmdc.

The installed cpmdc.pc, cpmdc-restart.pc, and libcp2k.pc files derive prefix and includedir from ${pcfiledir}, using the relative path from the pkg-config directory to those locations. -Dlibdir=., a nested libdir, a libdir that contains .., and an absolute includedir under the prefix stay inside the prefix. A directory that cannot be expressed as one relative path fails at configure time.

Install the Python package¶

Release tags publish wheels for Linux x8664 and aarch64 (manylinux2 28) and macOS arm64 (macOS 15 or newer). One wheel per platform serves CPython 3.10 and newer; CI tests 3.10 to 3.13. The ase extra installs ASE for cpmdc.ase:

pip install "cpmdc[ase]"
python -c "import cpmdc; print(cpmdc.find_library())"

The second command prints the libcpmdc inside the installed package. That library is the default build: the reference evaluator, without OpenCPMD and without MPI, so Session.available() is false. The wheel carries libgfortran and schema/Potentials.capnp. A periodic cell needs no other tool: the package encodes each step as ForceInput itself. The capnp command is needed only to encode a CPMDParams text file, and cpmdc.find_schema() returns the schema to encode it against. The test extra adds pytest for tests/python. To evaluate with OpenCPMD, build libcpmdc with -Dwith_cpmd=true and set CPMDC_LIBRARY to it; the variable takes precedence over the copy in the wheel.

On other platforms pip builds the sdist. That needs the C, C++, and Fortran compilers, Rust (cargo, for the minimage subproject), the capnp command, and network access for the Meson subprojects. The same build from a checkout:

pip install ".[ase]"

Build the docs¶

pixi run -e docs docbld

The build reference lists the other Pixi tasks. The published site is cpmdc.rgoswami.me.
