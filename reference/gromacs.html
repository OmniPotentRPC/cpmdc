GROMACS interface reference¶

libcpmdc_gromacs answers the libcp2k C API of GROMACS’ CP2K QM/MM interface with cpmdc_session_calculate_au() calls. Run GROMACS on cpmdc forces builds GROMACS against it and sets up a run.

Input file¶

The file is CP2K input in form, because grompp checks it for CHARGE, MULTIPLICITY, RUN_TYPE ENERGY_FORCE, COORD_FILE_FORMAT PDB, CHARGE_EXTENDED TRUE, and COORD_FILE_NAME and refuses @INCLUDE. GROMACS stores it in the .tpr, writes it out at mdrun as md_cp2k.inp with the name of the PDB file it generates, and passes both to the library. The PDB file gives each atom’s element, whether it is QM or MM, and each MM atom’s charge. The cpmdc settings are a &CPMDC section inside &FORCE_EVAL:

Key

Meaning

PARAMS path

the CPMDParams message; a relative path is relative to mdrun’s directory. Required

CELL PERIODIC

send the GROMACS box as the cell; the default when every atom is QM

CELL NONE

send no cell, so the deck’s cell holds the QM region; the default with MM atoms

EMBEDDING MECHANICAL

add the QM-MM Coulomb energy and forces of QM_CHARGES and the MM charges

EMBEDDING NONE

add nothing; allowed only when no MM atom carries a charge

QM_CHARGES q ...

one classical charge per QM atom, in index-group order; required by MECHANICAL

EWALD_RCUT r

real-space cutoff of the QM-MM Ewald sum in nm; default the smaller of 1 nm and half the smallest box height

EWALD_PRECISION p

erfc(alpha rcut) = p, and the reciprocal cutoff 2 alpha sqrt(-ln p); default 10-8 as assigned in tools/gromacs/cpmdc_gromacs.c

QM_RANKS ALL

under an MPI GROMACS, every rank of mdrun takes part in one cpmdc calculator; the default

QM_RANKS 1

rank 0 alone runs the QM calculation, the other ranks wait for its result

Everything outside &CPMDC is checked and otherwise ignored: the method is the CPMDParams deck, not CP2K’s &DFT. GROMACS’ generated input (qmmethod = PBE or BLYP) has no &CPMDC section and is refused.

The library writes one log, the CP2K output file GROMACS names (md_cp2k.out): the cpmdc version, the atom counts, the cell and embedding modes, the number of ranks and of QM ranks, the Ewald parameters in Bohr, and, for the first step, the backend (opencpmd, or reference for the evaluator of a build without OpenCPMD) and the QM and QM-MM energies. A refused input or a failed step prints cpmdc-gromacs: and the reason to stderr and to that log and stops mdrun with status 1, because the libcp2k API returns no errors.

Units¶

cpmdc works in Bohr and Hartree; GROMACS in nm, kJ/mol, and ps. GROMACS’ QM/MM module converts with its own constants from src/gromacs/math/units.h (CODATA 2018), so the library receives Bohr and returns Hartree and Hartree/Bohr. cpmdc.gromacs reproduces the factors bit for bit:

Cell and positions¶

GROMACS sends every atom, QM and MM, each step, after putting each into the box. GROMACS 2024 and 2025 send the box as box_d[3 i + j] = box[j][i], and GROMACS 2026 as box_d[3 i + j] = box[i][j], one lattice vector after the other, which is CP2K’s layout. GROMACS’ box is lower triangular, so the two differ only in where the zeros are, and the library reads either back as one lattice vector per row, the layout of cpmdc_session_calculate_au(); any triclinic shape GROMACS accepts passes through.

A wrapped atom jumps by a lattice vector. The library unwraps the QM atoms against their positions of the previous step, nearest image, so each follows a continuous path and wavefunction extrapolation sees smooth steps. With CELL NONE the first step also puts every QM atom at the nearest image of the first one, so the QM region starts whole. With CELL NONE cpmdc moves the QM region to the middle of the deck’s cell on every step, by its centre of mass, and removes the net force the cell would leave (CPMDC_RECENTER in environment variables), so the QM energy and forces do not depend on where the region has diffused to. The cell must still hold the region with room for its density; CPMDC_RECENTER_MARGIN makes a step fail when an atom comes closer to a face than that.

Embedding¶

GROMACS’ CP2K interface assumes electrostatic embedding: grompp zeroes the charges of the QM atoms, removes the bonds, angles, and dihedrals within the QM group, excludes QM-QM Lennard-Jones, and keeps QM-MM Lennard-Jones and the bonded terms that cross the boundary. The QM-MM Coulomb interaction is then the QM program’s job [1].

libcpmdc_gromacs provides mechanical embedding. EMBEDDING MECHANICAL adds the Coulomb energy of fixed point charges on the QM atoms, QM_CHARGES, with the MM charges of the PDB file, and its forces on both sides:

  • a periodic box: an Ewald sum with the conventions of GROMACS’ PME, the real-space term erfc(alpha r)/r over every image within rcut, the reciprocal term over k up to the cutoff above, and the neutralizing background -pi Q_QM Q_MM / (V alpha^2) of a non-neutral QM or MM part; the QM-QM and MM-MM sums are not included, since GROMACS’ PME already has MM-MM and the QM charges are zero in GROMACS;

  • no box: the direct sum.

The returned energy is the QM energy plus that Coulomb energy; both appear in Quantum En.. An MD step adds O(N_k (N_QM + N_MM)) work for the reciprocal sum.

Not implemented:

  • electrostatic embedding: the MM charges do not polarize the QM density. cpmdc_session_calculate_au() takes no external potential, so EMBEDDING ELECTROSTATIC is refused;

  • link atoms across a QM-MM covalent bond; &LINK sections are refused;

  • a relative dielectric constant other than 1 in the QM-MM sum;

  • PDB charges have six decimals, the precision of GROMACS’ file.

QM virial¶

GROMACS adds the QM/MM forces through its ForceWithVirial buffer, whose forces enter the virial only through addVirialContribution(), and the released QM/MM module never calls it (the GROMACS manual notes the missing virial [1]), so an unpatched GROMACS reports a pressure without the QM and QM-MM terms. The patch makes the module call libcp2k’s cp2k_get_stress_tensor() on each step that needs the virial, on the main rank only, since GROMACS sums the virial over ranks, and add

Xi = -0.5 * sigma * V * HARTREE_TO_KJ_PER_MOL

in kJ/mol, GROMACS’ -0.5 sum r (x) f convention. sigma is CP2K’s stress, column-major, in Hartree/Bohr3, positive under compression; sigma V is the virial W = -dE/d(strain) of the C ABI and ASE’s stress is -sigma. V is the box volume in Bohr3. With no kinetic energy, GROMACS’ pressure is then sigma.

libcpmdc_gromacs returns the strain derivative of the energy it returned, for a symmetric strain that moves every atom with the box:

  • CELL PERIODIC: cpmdc’s stress for the cell, from cpmdc_session_calculate_au();

  • CELL NONE: the symmetric part of sum x (x) f over the QM atoms. The QM forces sum to zero, since cpmdc removes the net force of the isolated cell, so the sum does not depend on the origin of x. Without that (CPMDC_RECENTER=off) a QM region at X with net force F adds X (x) F, which grows as the region drifts and as the barostat scales it away from the origin. The grid still leaves a small torque, and a symmetric strain does not see the antisymmetric part;

  • EMBEDDING MECHANICAL with a box: plus the strain derivative of the QM-MM Ewald sum, its real-space, reciprocal, and background terms.

It reports the stress as unavailable with no box (pbc = no), and with CELL PERIODIC when cpmdc computes no stress: an isolated deck, or CPMDC_STRESS=0. The patched GROMACS then writes once to md.log that the QM program returned no stress tensor, and the pressure lacks the QM terms; md_cp2k.out logs the outcome of the first request.

Several ranks¶

A GROMACS built with -DGMX_MPI=ON calls cp2k_create_force_env_comm on every rank, with the Fortran handle of its simulation communicator, and then each step sends every rank the positions of all atoms and reads the forces of its home atoms back. GROMACS refuses separate PME ranks with QM/MM, so every rank of that communicator makes each call and the library can use collectives on it. libcpmdc_gromacs is built with MPI when Meson finds MPI for C, the same MPI GROMACS is built with, and then:

  • duplicates the communicator, so cpmdc’s traffic and error handler stay off GROMACS’ own;

  • reads the input and the PDB file on rank 0 and broadcasts the atom counts, the QM atoms, and the CPMDParams message;

  • hands the duplicate to cpmdc with cpmdc_adopt_calculator_comm() before the first session, with every rank as one calculator (QM_RANKS ALL), or MPI_COMM_SELF on rank 0 (QM_RANKS 1). It does so on one rank too: GROMACS has started MPI, and OpenCPMD sets up a communicator only when it starts MPI itself;

  • each step broadcasts rank 0’s positions and box, so every QM rank evaluates identical input whatever GROMACS’ decomposition, adds the embedding on rank 0, and broadcasts rank 0’s energy and forces.

The forces GROMACS reads are therefore identical on every rank, and domain decomposition changes which rank applies a force, not its value, including for QM molecules whose atoms sit in different domains. With QM_RANKS 1, or the reference evaluator, the QM forces are those of a one-rank run; with OpenCPMD on several ranks they differ from them by the order of its parallel sums (see the OpenCPMD runs). GROMACS reads the energy on its main rank only, so Quantum En. counts it once.

A library built without MPI stops a cp2k_create_force_env_comm call with the reason.
