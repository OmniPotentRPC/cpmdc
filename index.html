cpmdc¶

Overview¶

cpmdc is the C ABI layer for embedding OpenCPMD in OmniPotentRPC tools. It keeps the public boundary small and language-neutral. Hosts pass method setup once, pass geometry for each calculation step, and get native C results or a serialized result message back.

Message

Owns

Typical lifetime

CPMDParams

method setup, CPMD sections, pseudopotentials, backend hints

one session

ForceInput

positions, atomic numbers, optional cell, requested units

one calculation step

PotentialResult

energy, forces, status, message

one calculation result

The ABI does not expose C++ types, Rust types, or a second JSON/TOML options language. All portable configuration lives in schema/Potentials.capnp; the C library decodes those bytes with generated capnp-c readers and renders the CPMD INPUT deck internally.

Long-running drivers create one CPMDCSession from CPMDParams, then pass ForceInput per step. The result-carrier call, cpmdc_session_calculate_result(), writes the same PotentialResult message used by rgpot RPC clients.

session_accept_topology fixes the topology only after an evaluation call passes its argument checks and collective orbital preflight. A rejected preflight leaves the topology configurable. A reordering of those elements stays on the session. Later steps may change coordinates, units, and the 3 by 3 cell; a different composition requires a new session.

Questions and bug reports¶

Ask questions and report bugs on the GitHub issue tracker. Check Troubleshooting first, because it lists known failures with their fixes. Its last section lists what to put in a new report.

Build and Test¶

meson setup build -Dwith_tests=true
meson compile -C build
meson test -C build --print-errorlogs

The default build does not need an OpenCPMD checkout. It uses a deterministic reference evaluator to test the public ABI, parser, feature table, sessions, result sizing, and unit conversion.

Reference at a glance¶

The C ABI reference lists every public call with its contract, the plane-wave scaffold reference does the same for the opt-in scaffold, and CPMD option mapping says which CPMDParams field or feature ID carries each line of the CPMD manual. An OpenCPMD archive build links the same C ABI against libcpmd.a.

Citation¶

Cite cpmdc with the record in CITATION.cff at the root of the repository. It gives the author, the version, the license, and the repository in the Citation File Format. GitHub reads that file and offers the record as “Cite this repository” on the repository page, as the GitHub documentation on citation files describes. The Citation File Format record lists the Zenodo concept DOI for all versions. This release has no version DOI. codemeta.json is the CodeMeta 2.0 record, and .zenodo.json is the Zenodo deposit metadata. version-sync writes the version in CITATION.cff, codemeta.json, and .zenodo.json from version.txt. .zenodo.json carries a version field. Zenodo lists version as optional deposit metadata. release-assert checks the cog copies and the version fields in codemeta.json and .zenodo.json, and fails when one differs from version.txt. The Citation File Format record references CPMD. Its reference uses the citation in the CPMD manual and the version, license, and repository of CPMD-code/CPMD. It credits the CPMD consortium, the author that the manual names. IBM Corp and the MPI für Festkörperforschung Stuttgart hold the copyright.

An OpenCPMD archive build computes its energies and forces with OpenCPMD, so a paper that reports them cites OpenCPMD as well. OpenCPMD ships no citation file; name it with its repository, github.com/OpenCPMD/CPMD, and the version or commit that the archive was built from.
