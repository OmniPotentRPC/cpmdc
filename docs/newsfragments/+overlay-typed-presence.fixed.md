The deck renderers and the configuration the embed records apply the same precedence to the functional, cutoff, charge, and multiplicity lines cpmdc writes, so a typed `dft` section naming `BLYP` next to an overlay `xcFunctionals` no longer writes `FUNCTIONAL BLYP` while recording the overlay functional. A value a typed field sets beats the overlay, the overlay beats a schema default, a typed section beats the top-level field, and the overlay cutoff is converted from eV to Ry before it is written. Every set overlay scalar is rejected, whether or not a typed field also sets it, next to the typed-section directive that renders the same setting: `FUNCTIONAL` in a typed `dft` section, or `CUTOFF`, `CHARGE`, or `MULTIPLICITY` in a typed `system` section. Without an overlay, a `FUNCTIONAL` directive in a typed `dft` section or a `DFT.FUNCTIONAL` set directive is rejected when the deck is rendered, instead of following the rendered `FUNCTIONAL` line in the same `&DFT` section.
