`CPMDCCalculator`, `cpmdc-ipi`, `cpmdc-ipi-c`, and native deck rendering now use the same float64 rank cutoff for periodic cells and preserve every representable cell component in generated CPMD input; the C library and the Python package decide the rank with the same iteration, so they agree on cells within rounding of the cutoff. Cells whose volume would underflow, duplicate or invalid i-PI `batch_size` values, non-UTF-8 `INIT` data, and negative or non-finite connection waits now report their cause instead of being treated as an ordinary request. Both i-PI drivers judge the cell volume on the Bohr values they receive, `cpmdc-ipi-c` stops on a non-finite position or cell value as `cpmdc-ipi` does, and the virial of `cpmdc_session_calculate_au()` and of both drivers no longer cancels to zero for an accepted near-singular cell; a cell volume above the float64 range or a non-finite virial is reported instead of being sent.
