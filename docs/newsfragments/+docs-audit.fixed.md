Documentation audit against the code. The `cpmdc_session_calculate_au()` header comment now states the session it needs, buffer ownership, collective use with OpenCPMD, the stub result, the centre of mass recentring, the topology fixed on the first evaluation call that passes its argument checks, the repeat match, and every `-1` cause with what is left unwritten. For `cell_bohr`, a NULL cell and an all-zero cell are read the same way by the deck, but the call keeps an all-zero cell as a step that has a cell, so the two are different steps for the repeat match and for stored OpenCPMD orbitals. The other public header comments gain the missing return codes, side effects, and ranges: `cpmdc_set_params()`, `cpmdc_configure()` (a `cpmd` arm with a `common` overlay is merged, not rejected), `cpmdc_energy_gradient()` (a step without a cell skips full setup only when the latched basis matches and the latched state also has no cell, since `embed_cell_moves_in_place` returns false when `has_cell` is 0; it then starts from the stored orbitals within `CPMDC_WARM_RMSD`, default 0.15 Angstrom, or from the deck's guess without full setup beyond that limit, and any other call runs full setup for a cold SCF), `cpmdc_adopt_calculator_comm()`, `cpmdc_adopted_comm()`, the session `set_params` and `configure` calls and `create_from_config`, `cpmdc_session_calculate_forces()`, `cpmdc_session_calculate_result()`, `cpmdc_capabilities_result()`, `cpmdc_version()` (including the `cpmdc-stub/` prefix of the link stub), `cpmdc_finalize()`, `cpmdc_last_error()`, `cpmdc_restart_write_path()`, and `cpmdc_restart_expand_species_symbols()`.

`cpmdc_bind_calculator()` and the MPI how-to now describe how ranks are divided. `ranks_per_calc` is the size of every group, and zero or less means the world size. The world size must be a multiple of it, and there is no remainder group. A value that does not divide the world size, or that is above it, returns `-1` on every rank and splits nothing. Group `g` holds world ranks `g * ranks_per_calc` to `(g + 1) * ranks_per_calc - 1`, and a later call returns `world_rank / ranks_per_calc` for its own value without splitting again, also after `cpmdc_adopt_calculator_comm()`. `cpmdc` calls `MPI_Init` only in OpenCPMD builds, and it does so before it looks at the value. The reference build and the link stub return `-1` from `cpmdc_bind_calculator()` without calling MPI, and `cpmdc_adopt_calculator_comm()` returns `-1` there until the host has started MPI. The `cpmdc_session_set_params()` comment lists allocation failure among its errors; it returns `-1` with the text `out of memory`.

The `cpmdc_pwscale.h` comments give the limits behind `CPMDC_PWSCALE_ERR_ARG`, state that `CPMDC_PWSCALE_ERR_NOFFTW` is returned by `bench/pwscale_fft.c` when built without FFTW or when thread initialisation or plan creation fails, and say that the rank timer ends after the rank-ordered sum. The C ABI reference, environment reference, wavefunction-state explanation, install how-to, Python how-to, ASE how-to (`constant_cutoff`), socket how-to (`cpmdc-ipi` status 2), and quickstart (every Meson test suite from `meson.build`) match the code.

New tests cover the claims that had none: `test_session_calculate_au` checks the NULL and all-zero cell repeat match and, on an OpenCPMD build, the warm start source for each cell kind, and `bind-calculator-stub` and `bind-calculator-shell` run `cpmdc_bind_calculator()` on four ranks.
