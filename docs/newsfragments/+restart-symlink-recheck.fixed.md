On POSIX, publishing through a `RESTART` symlink rechecks the chain immediately before `renameat` and fails if a followed symlink or the final component is no longer what was resolved, so a link swapped for a regular file in that window is not overwritten. An absent final name uses `renameat2` with `RENAME_NOREPLACE` where the headers and kernel provide it. If that operation is unavailable, plain `renameat` leaves a gap in which a newly appeared name can be overwritten. Replacing an existing file has the same gap because POSIX has no rename that succeeds only when the directory entry is the same inode.
