#+TITLE: Build the OpenCPMD archive for embedding
#+OPTIONS: toc:nil todo:nil num:nil author:nil title:t

* Goal
Produce an OpenCPMD build tree whose ~lib/libcpmd.a~ can be linked into the
shared ~libcpmdc.so~ and evaluated repeatedly from one host process.
A stock OpenCPMD archive does not work inside a host: ~libcpmdc~ imports
routines that only the patches add, the shared link stops on code built
without ~-fPIC~, and the unpatched SCF driver drops the forces and the
orbitals that ~cpmdc~ reads after each call.
The patches in ~tools/~ and one compiler flag fix those.
~opencpmd_c_mem_addrs.patch~ makes ~cGetMemAddrs~ return the address as
~size_t~.
GCC 14 rejects the stock return of a pointer from that function.
~cuda_get_address~ stores the ~size_t~ that function returns.

* Patches

| Patch | File patched | Without it |
|-------+--------------+------------|
| ~opencpmd_embed_rinitwf.patch~ | ~src/rinitwf_driver.mod.F90~ | a warm call still builds the wavefunction guess and then discards it |
| ~opencpmd_embed_geometry.patch~ | ~src/embed_ctrl.mod.F90~, ~src/initrun_driver.mod.F90~, ~src/SOURCES~ | ~initrun~ still writes ~GEOMETRY~ after ~embed_set_write_files(.FALSE.)~, and ~rwfopt~ has no ~embed_ctrl~ to read |
| ~opencpmd_embed_rwfopt.patch~ | ~src/rwfopt_utils.mod.F90~ | ~rwfopt~ deallocates ~fion~ on return and starts every SCF from a fresh guess, and ~cpmd_embed_c_api.F90~ does not compile |
| ~opencpmd_converged_state.patch~ | ~src/updwf_utils.mod.F90~ | the optimiser applies one more update after convergence, so the saved orbitals no longer match the reported energy and forces; steepest descent with ~iproj <= 1~ also needs its ~gemax~ reset before the convergence check |
| ~opencpmd_kpoints_inputfile.patch~ | ~src/rkpnt_utils.mod.F90~ | the k-point report reads the host's ~argv[1]~ as the input file name and stops with ~STOP 12345~ when it is missing or longer than 80 characters |
| ~opencpmd_stopgm_return.patch~ | ~src/error_handling.mod.F90~ | a CPMD stop inside an evaluation takes the ~my_stopall~ path, which OpenCPMD writes to end the run |
| ~opencpmd_tistopgm.patch~ | ~src/timer.mod.F90~ | ~tistopgm~ indexes ~trace_depth~ before ~tistart~, while the depth is still ~HUGE(0)~, and the process faults before ~LocalError~ |
| ~opencpmd_c_mem_addrs.patch~ | ~src/c_mem_utils.c~ | ~cGetMemAddrs~ returns a ~size_t~ pointer, and GCC 14 stops on that conversion |
| ~opencpmd_embed_teardown.patch~ | ~src/embed_teardown.mod.F90~, ~src/embed_ctrl.mod.F90~, ~src/SOURCES~, and 33 modules with first-call state | a second setup in one process, after a basis change or a ~stopgm~, stops in ~ratom~ with ~allocation problem~ or faults, because the arrays of the first setup are still allocated |
| ~opencpmd_embed_extrapolate.patch~ | ~src/embed_ctrl.mod.F90~, ~src/control_test_utils.mod.F90~, ~src/rwfopt_utils.mod.F90~ | ~EXTRAPOLATE WFN~ in the deck is dropped with a warning, and ~libcpmdc~ does not link, because it reads ~embed_extrapolation_used~ |
| ~opencpmd_omp_info.patch~ | ~src/rggen_utils.mod.F90~ | a calculator that spans nodes with unequal numbers of ranks calls ~MPI_Allreduce~ with different counts in the report and can stop before the first electronic iteration |
| ~opencpmd_pcg_step.patch~ (optional) | ~src/pcgrad_driver.mod.F90~ | the PCG line minimisation can suppress its interpolated step for strict orbital targets; see [[file:wavefunction-optimiser.org][the optimiser how-to]] |

The loops below apply every patch but the optional ~pcg_step~;
~scripts/ci/build_opencpmd.sh~ applies it too.

[[file:../explanation/opencpmd-patches.org][How the OpenCPMD patches work]]
explains what each patch changes inside CPMD and why ~libcpmdc~ needs it.

~tests/test_opencpmd_patch_integrity.py~ checks that the patches are portable
unified diffs against the files named above.
Apply ~opencpmd_embed_rinitwf.patch~ before the rwfopt patch.
~rwfopt~ reads ~embed_have_orbitals~ from ~rinitwf_driver~.
Apply ~opencpmd_embed_geometry.patch~ before that rwfopt patch as well:
~rwfopt~ reads ~embed_ctrl~.
The rwfopt, converged-state, k-point, stop, and timer patches are the
commits on [[https://github.com/OpenCPMD/CPMD/pull/9][OpenCPMD pull request 9]]
(branch ~embedding-hooks~, ~43cf4e7~) and apply in sequence to OpenCPMD
commit ~062582b~.
Apply ~opencpmd_c_mem_addrs.patch~ with them.
Apply ~opencpmd_embed_teardown.patch~ after those: it adds to the ~embed_ctrl~ of the geometry patch and calls ~embed_reset_warm_orbitals~ from the rwfopt patch.
Apply ~opencpmd_embed_extrapolate.patch~ after the teardown patch, whose lines in ~embed_ctrl~ it follows.

* Build a patched tree
Start from an OpenCPMD source checkout and apply the patches before the first
build:

#+begin_src bash
git clone https://github.com/OpenCPMD/CPMD.git opencpmd
cd opencpmd
git checkout 062582b7cfd832d36f88f504cd08e4ead42eb404
for p in embed_rinitwf embed_geometry embed_rwfopt converged_state \
         kpoints_inputfile stopgm_return tistopgm c_mem_addrs \
         embed_teardown embed_extrapolate omp_info; do
  patch -p1 < /path/to/cpmdc/tools/opencpmd_$p.patch
done
#+end_src

The OpenCPMD sample ~LINUX-X86_64-GFORTRAN-MPI~ sets ~LIBS~ to one person's
library path.
Copying that file and adding ~-fPIC~ leaves the path in the build.
~cpmdc~ ships ~tools/LINUX-X86_64-GFORTRAN-MPI-PIC~ for the command below.
It calls ~mpif90~ and ~gcc~ from ~PATH~, adds ~-fPIC~ and
~-ffp-contract=off~ to ~FFLAGS~ and ~CFLAGS~, and sets ~LIBS~ to
~-lopenblas~.
The aarch64 file is ~tools/LINUX-AARCH64-GFORTRAN-MPI-PIC~.
The section Building OpenCPMD for mixed clusters below says when to
use each file.
When ~mpif90~ accepts it, ~FFLAGS~ also gains ~-fallow-argument-mismatch~.
~mp_bcast_byte~ broadcasts the bytes of its first argument, and one
procedure calls it with several derived types.
gfortran 10 and later stop on those calls without the flag.
That OpenBLAS build has to export the LAPACK symbols.
~libcpmdc~ is a shared library; a member of ~libcpmd.a~ compiled without
~-fPIC~ fails the link with a ~R_X86_64_PC32~ relocation error.
Copy the shipped file into the clone, then configure and build:

#+begin_src bash
cp /path/to/cpmdc/tools/LINUX-X86_64-GFORTRAN-MPI-PIC configure/
./configure.sh -DEST=/path/to/opencpmd-build LINUX-X86_64-GFORTRAN-MPI-PIC
make -C /path/to/opencpmd-build -j 8
ls /path/to/opencpmd-build/lib/libcpmd.a /path/to/opencpmd-build/obj/timetag.o
#+end_src

~/path/to/opencpmd-build~ is the ~cpmd_root~ passed to Meson.
The ~cpmdc~ build reads ~lib/libcpmd.a~, the module files in ~obj/~, and the
headers in ~src/~.

* Patch a tree that is already built
When the tree was built before the patches were applied, patch the source and
rebuild only the affected members:

#+begin_src bash
cd /path/to/opencpmd-source
for p in embed_rinitwf embed_geometry embed_rwfopt converged_state \
         kpoints_inputfile stopgm_return tistopgm c_mem_addrs \
         embed_teardown embed_extrapolate omp_info; do
  patch -p1 < /path/to/cpmdc/tools/opencpmd_$p.patch
done
/path/to/cpmdc/tools/rebuild_opencpmd_embed.sh /path/to/opencpmd-build
/path/to/cpmdc/tools/rebuild_opencpmd_omp_info.sh /path/to/opencpmd-build
#+end_src

~rebuild_opencpmd_embed.sh~ recompiles the object of the embedding patch, ~error_handling.mod.o~, ~embed_ctrl.mod.o~, ~control_test_utils.mod.o~, ~rinitwf_driver.mod.o~, ~initrun_driver.mod.o~, ~rwfopt_utils.mod.o~, ~updwf_utils.mod.o~, ~rkpnt_utils.mod.o~, ~timer.mod.o~, ~c_mem_utils.o~, the 33 modules of the teardown patch, and ~embed_teardown.mod.o~ after them, and ~scex_utils.mod.o~ for the module order, with one Make job, then replaces those members with ~ar r~ and runs ~ranlib~.
It runs one job because gfortran stores a copy of ~Scex_t~ inside
~rwfopt_utils.mod~: a parallel rebuild can leave the two module files naming
different components.
It calls ~ar~ directly because the generated Makefile sets ~AR~ without an
operation letter, so its archive rule does not replace members.
~MAKE~ and ~AR~ in the environment override the programs it runs.

~opencpmd_omp_info.patch~ corrects report collectives when one calculator
spans nodes with unequal numbers of ranks. Every rank uses the I/O node's
array size; otherwise the report calls ~MPI_Allreduce~ with different counts
and can stop before the first electronic iteration. The separate
~rebuild_opencpmd_omp_info.sh~ helper rebuilds ~rggen_utils.mod.o~ and
replaces that archive member. Relink ~libcpmdc~ against the corrected archive.

The reporting regression compiles the actual native routine with an MPI
fixture representing unequal node populations. Inside an allocation with
at least three ranks, run:

#+begin_src bash
/path/to/cpmdc/tools/check_opencpmd_omp_info.sh /path/to/opencpmd-source /path/to/build/omp-info
#+end_src

The corrected routine exits zero. The unpatched control reports
~inconsistent native report counts~ and exits nonzero. This checks report
collectives; energy and force evaluations require their native tests.

* Link and check
OpenCPMD leaves ~timetag~ out of ~libcpmd.a~ and links ~obj/timetag.o~ into
~cpmd.x~. ~header~ calls ~timetag~, so the embed link needs that object too.
Build it from the configured tree before ~meson setup~:

#+begin_src bash
make -C /path/to/opencpmd-build/obj -f /path/to/opencpmd-build/Makefile timetag.o
#+end_src

#+begin_src bash
meson setup build-cpmd -Dwith_cpmd=true -Dcpmd_root=/path/to/opencpmd-build
meson compile -C build-cpmd
nm -D build-cpmd/libcpmdc.so | grep -c ' T cpmdc_'
#+end_src

The last command counts the exported ~cpmdc_*~ symbols.
The export list hides every other symbol of the archives except the MPI
Fortran sentinels, which must stay global (see
[[file:../explanation/opencpmd-patches.org][How the OpenCPMD patches work]]).
The first evaluation needs the pseudopotential directory in
~CPMDC_PSEUDO_DIR~; the [[file:../tutorials/first-energy.org][first energy
tutorial]] runs one.
Stress tensors, which ~PotentialResult.stress~ carries for periodic cells, need
no extra patch: ~cpmdc~ sets ~cntl%tpres~ before the SCF and copies
~paiu/omega~ afterwards.
An isolated cell does not set the snapshot. The box has a volume, and CPMD
does not compute the tensor.

* Building OpenCPMD for mixed clusters
A binary that runs on more than one CPU type must not be built with
~-xHost~, ~-march=native~, or ~-axCORE-AVX512~.
~-xHost~ and ~-march=native~ bind the object code to the CPU that
compiled it.
~-axCORE-AVX512~ is Intel's multi-target flag, and the binary it
produces does not run on a non-Intel CPU.
Stock OpenCPMD files that pass those flags include
~INTEL-AMD-IFORT-OPENMPI~ and ~INTEL-SKYLAKE-IFORT-OPENMPI~.
Do not copy them for a shared cluster.
One binary per microarchitecture belongs in EESSI
(Dröge et al., Softw. Pract. Exp. 53, 176 (2023),
doi:10.1002/spe.3075).

~cpmdc~ ships two configure files that set the instruction set explicitly.
~tools/LINUX-X86_64-GFORTRAN-MPI-PIC~ passes ~-march=x86-64~ on debug and
release ~FFLAGS~ and ~CFLAGS~.
GCC 11 on RHEL 9 defaults to x86-64-v2, and GCC 14 on RHEL 10 defaults
to x86-64-v3, which includes AVX2 and FMA.
~tools/LINUX-AARCH64-GFORTRAN-MPI-PIC~ passes ~-march=armv8-a~ on those
same flags.
Both add ~-fPIC~, because ~libcpmdc~ is a shared library, and
~-ffp-contract=off~.
~-ffp-contract=off~ stops the compiler from fusing a multiply and an
add into one instruction.
That keeps numeric results equal across build targets.
The same flag is on ~cpmdc~ C and Fortran arguments.
Copy the file that matches the machine into ~configure/~:

#+begin_src bash
cp /path/to/cpmdc/tools/LINUX-AARCH64-GFORTRAN-MPI-PIC configure/
./configure.sh -DEST=/path/to/opencpmd-build LINUX-AARCH64-GFORTRAN-MPI-PIC
#+end_src

On x86_64, use ~LINUX-X86_64-GFORTRAN-MPI-PIC~ in that command instead.

OpenBLAS and FFTW choose their own kernels at run time when they were
built that way.
~meson.build~ links OpenBLAS, or FlexiBLAS when that library is
present, and FFTW3, including ~fftw3_omp~ when it is present.
Check OpenBLAS with ~openblas_get_config()~.
The returned string contains ~DYNAMIC_ARCH~ when the library selects a
kernel for the CPU it is running on.
A build without ~DYNAMIC_ARCH~ can contain one microarchitecture and
fault on a CPU that lacks it.
Check FFTW in the build's ~config.log~ or the package recipe.
Runtime selection is on when several SIMD codelet options were enabled
together, for example ~--enable-sse2~, ~--enable-avx~, ~--enable-avx2~,
~--enable-avx512~, or ~--enable-neon~.
A library built with only one of those runs only that set.
