#+TITLE: Run under mpirun
#+OPTIONS: toc:nil todo:nil num:nil author:nil title:t

* Goal
Run a host that embeds ~cpmdc~ on several MPI (Message Passing Interface)
ranks, so that CPMD parallelises each self-consistent field (SCF) calculation
over the ranks, and keep every rank's view of the result consistent.
This page needs an OpenCPMD build of ~cpmdc~; the default build runs the
reference evaluator on each rank independently.

* The rules
1. Start every rank of the host under ~mpirun~.
   CPMD initialises MPI on the first evaluation when the host has not.
2. Every rank makes the same ~cpmdc~ calls with the same messages in the same
   order.
   An evaluation is collective over the ranks of its calculator.
3. Take the energy and forces from the first rank of each calculator, CPMD's
   parent rank, and broadcast them to the other ranks.
   The other ranks return from the call with values of their own.
   In a 4-rank water single point all four printed the parent's energy and
   forces, but in a 4-rank dimer search, where every rank also ran the
   host's optimizer, rank 1 took 3 steps on different curvatures while rank 0
   took 5, and only rank 0's results matched an independent ~cpmd.x~ run.
4. Keep one ~CPMDCSession~ per calculator.
5. Call ~MPI_Finalize~ on every rank before the host exits.
   ~cpmdc_finalize()~ does not finalize MPI.

* One calculator over all ranks
Without further setup, CPMD uses ~MPI_COMM_WORLD~, so all ranks form one
calculator:

#+begin_src bash
export CPMDC_PSEUDO_DIR=/path/to/pseudopotentials
mpirun -np 16 ./host params.bin step.bin
#+end_src

Rank 0 of ~MPI_COMM_WORLD~ is then CPMD's parent rank.

* Several calculators in one job
~cpmdc_bind_calculator(ranks_per_calc)~ splits ~MPI_COMM_WORLD~ into groups of
~ranks_per_calc~ consecutive ranks.
Each group becomes one CPMD calculator with its own communicator and its own
wavefunction, running the same deck.
Call it on every rank, once, before the first evaluation:

#+begin_src c
#include <cpmdc.h>
#include <mpi.h>

int main(int argc, char **argv) {
  MPI_Init(&argc, &argv);
  int group = cpmdc_bind_calculator(4); /* 16 ranks -> 4 calculators */
  if (group < 0) {
    /* world size not a multiple of 4, or no CPMD backend */
    MPI_Abort(MPI_COMM_WORLD, 1);
  }
  int world_rank = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &world_rank);
  int is_parent = (world_rank % 4) == 0;

  /* group 0 evaluates image 0, group 1 image 1, ... */
  /* ... create one session, evaluate, share the parent's result ... */

  cpmdc_finalize();
  MPI_Finalize();
  return 0;
}
#+end_src

| Argument or result | Meaning |
|--------------------+---------|
| ~ranks_per_calc > 0~ | ranks per calculator; the world size must be a multiple of it |
| ~ranks_per_calc <= 0~ | one calculator over the whole world |
| return value ~>= 0~ | index of this rank's calculator, ~world_rank / ranks_per_calc~ |
| return value ~-1~ | the split was refused, or the library has no CPMD backend (the default build and the stub) |

A second call returns the same index without splitting again.
The group's first rank, world rank ~group * ranks_per_calc~, is its parent
rank.
~cpmdc~ remembers the split in ~embed_calculator_bound~.
~mp_start~ assigns ~mp_comm_world~ only when CPMD itself calls ~MPI_Init~,
and ~cpmdc_bind_calculator~ has already initialised MPI and stored the
calculator communicator by the time setup reaches ~mp_start~.

* A communicator the host already split
A host that has already split its ranks passes that communicator to
~cpmdc_adopt_calculator_comm(comm, nbytes, ranks_per_calc)~.
[[https://rgpot.rgoswami.me][rgpot]] does this when it binds calculator groups.
Its MPI contract is the
[[https://rgpot.rgoswami.me/reference/mpi.html][rgpot MPI reference]], and the
messages those hosts share are the ones in the
[[file:../index.org][cpmdc overview]].
~nbytes~ is ~sizeof(MPI_Comm)~.
The call is collective on ~comm~.
It reads rank and size from ~comm~.
It does not call ~MPI_Init~ or ~MPI_Comm_split~.
The size check uses ~comm~.

When ~ranks_per_calc~ is greater than zero, the adopted size must equal it.
A different size returns -1, and ~cpmdc_last_error()~ names both numbers.
Zero or less skips that check.
The same positive ~ranks_per_calc~ on every rank gives every group the same
size, and the calculator indices are then unique.
The group must be one aligned block of ~size~ consecutive world ranks,
starting at a multiple of ~size~.
The calculator index is the lowest world rank in that block, divided by
~size~.
Any other layout returns -1 on every rank of the group, and
~cpmdc_last_error()~ says the communicator is not an aligned block.
Reversing the key order inside an aligned block does not change the index.
A striped split is refused: world ranks 0 and 2 in one group of size 2, and
ranks 1 and 3 in the other, would otherwise both receive index 0.

The handle is borrowed.
The call does not use ~MPI_Comm_dup~.
It stores the caller's communicator, and an OpenCPMD build also stores it in
~mp_comm_world~.
The caller keeps ownership and must not free the communicator until the last
session is destroyed or a later adopt replaces it.
An adopt after ~cpmdc_bind_calculator~ replaces the communicator that call
split, and the caller of bind cannot free that one.

~cpmdc_adopted_comm~ copies the stored handle back to the caller.
~cpmdc_bind_calculator~ remains the split for a host that has not split.
That split still runs once per process.

A later adopt replaces the communicator when no ~CPMDCSession~ exists.
Destroy every session first.
If any rank of the group has a live session, every rank returns -1,
~cpmdc_last_error()~ says a session is live, and the stored communicator
stays as it was.
That refusal is the same collective as the index, so one rank does not
return while another waits.
The index is the same rule for 1 group of 4 ranks, 2 groups of 2, and 4
groups of 1.

* Share the parent's result
The host owns the broadcast.
With one calculator over the whole world, broadcast from world rank 0:

#+begin_src c
double buf[1 + 3 * N_ATOMS];
if (world_rank == 0) {
  buf[0] = result.energy_h;
  memcpy(buf + 1, forces, sizeof(double) * 3 * N_ATOMS);
}
MPI_Bcast(buf, 1 + 3 * N_ATOMS, MPI_DOUBLE, 0, MPI_COMM_WORLD);
#+end_src

With several calculators, each group's parent broadcasts inside its group, and
a host that needs every group's result on every rank broadcasts once per
group over ~MPI_COMM_WORLD~.
An optimizer that runs on every rank must step from the broadcast values;
ranks that step from their own copies drift apart after the first step.

* One session per calculator
The OpenCPMD module state and the stored orbitals belong to the process, not
to a ~CPMDCSession~.
A second session keeps those orbitals when its functional, deck, cutoff, cell,
charge, multiplicity, and elemental composition match.
A different method or composition drops them on the next evaluation.
Run independent calculations, such as the images of a nudged elastic band, on
separate calculators, one session each.

* Finalize MPI
CPMD calls ~MPI_Init~ during its setup, and nothing in ~cpmdc~ calls
~MPI_Finalize~.
Open MPI 5 treats a rank that exits without ~MPI_Finalize~ as an abnormal
termination and kills the ranks still running; ~mpirun~ then reports a rank
"exiting improperly" and lists a missing finalize among the reasons.
Call ~MPI_Finalize~ on every rank, after ~cpmdc_finalize()~, as the example
above does.
When the host cannot restructure its exit path, register a handler with
~atexit~ that calls ~MPI_Finalize~ when ~MPI_Initialized~ reports true and
~MPI_Finalized~ reports false.

* Threads
CPMD also runs OpenMP threads inside each rank when OpenCPMD was built with
~-omp~.
Set ~OMP_NUM_THREADS~ per rank so that ranks times threads matches the cores
the job holds.
