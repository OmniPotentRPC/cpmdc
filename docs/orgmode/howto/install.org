* What gets built
A ~cpmdc~ build produces the shared libraries ~libcpmdc.so~ and ~libcpmdc_csvr~,
and a few helpers around them.
Outside a ~with_python~ build, ~libcpmdc_csvr~ records SONAME
~libcpmdc_csvr.so.0~.
The build has two modes, selected by the Meson option ~with_cpmd~:

| Mode | Option | Evaluator behind the C ABI | ~cpmdc_available()~ |
|------+--------+----------------------------+---------------------|
| Default | ~-Dwith_cpmd=false~ | deterministic reference evaluator, no OpenCPMD | 0 |
| OpenCPMD | ~-Dwith_cpmd=true -Dcpmd_root=DIR~ | OpenCPMD linked from ~DIR/lib/libcpmd.a~ | 1 |

Both modes export the same symbols.
A third target,
~libcpmdc_stub.a~, is a link-only placeholder: every call fails and ~cpmdc_available()~
returns 0.
The tests use it to check the ABI without a working evaluator.

| Artifact | Installed as | Purpose |
|----------+--------------+---------|
| ~libcpmdc.so~ | ~lib/libcpmdc.so.MAJOR~, or an unversioned ~lib/libcpmdc.so~ when ~with_python~ is on | the C ABI from ~include/cpmdc.h~ |
| public headers | ~include/cpmdc/cpmdc.h~, ~cpmdc_features.h~, ~cpmdc_export.h~, ~cpmdc_restart.h~, ~cpmdc_damp.h~ | declarations for hosts |
| ~libcpmdc_restart.a~ | ~lib/libcpmdc_restart.a~ | reader and writer for CPMD ~RESTART~ files |
| ~libcpmdc_csvr~ | ~lib/libcpmdc_csvr.so.0~ and ~lib/libcpmdc_csvr.a~ for ~default_library=shared~ and for ~default_library=static~. A ~with_python~ build installs ~lib/libcpmdc_csvr.a~ and an unversioned ~lib/libcpmdc_csvr.so~ | canonical sampling thermostat, not called by a session |
| ~cpmdc_csvr.h~ | ~include/cpmdc/cpmdc_csvr.h~ | declarations for that thermostat |
| ~cpmdc-restart~ | ~bin/cpmdc-restart~ | command-line front end to ~libcpmdc_restart~ |
| ~libcpmdc_damp.a~ | ~lib/libcpmdc_damp.a~ | damped electronic step; a session does not call it |
| pkg-config files | ~cpmdc.pc~, ~cpmdc-restart.pc~, ~cpmdc-damp.pc~ | compiler and linker flags |
| CMake package | ~lib/cmake/cpmdc/cpmdcConfig.cmake~, ~cpmdcConfigVersion.cmake~ | imported target ~cpmdc::cpmdc~; the version file accepts any release with the same major version |

The optional tools (~cpmdc-ipi-c~, the LAMMPS plugin, and ~libcpmdc_gromacs~)
are listed with the options that build them in the [[file:../reference/build-options.org][build reference]].

~MAJOR~ is the soversion, the first field of ~version.txt~.
A ~with_python~ build sets no soversion, because a wheel stores no symlinks.
~libcpmdc_csvr~ keeps its own soversion, 0, so a later change of the generator
layout can bump it without following that major.
A ~with_python~ build leaves that library unversioned for the same reason.

* Requirements
The checked-in Pixi manifest pins every build dependency.
Without Pixi, install the same set from your package manager:

| Dependency | Version in ~pixi.toml~ | Needed for |
|------------+------------------------+------------|
| Meson, Ninja | Meson 1.5.2 or newer, below 2; Ninja 1.11 or newer, below 2 | every build |
| Cap'n Proto (~capnp~ compiler) | 1.0.2 or newer, below 2 | generating the schema readers, encoding messages |
| C and Fortran compilers | any recent GCC and gfortran | every build |
| C++ compiler and Rust (~cargo~) | Rust 1.70 or newer, below 2 | the ~minimage~ subproject |
| pkg-config | 2.5.1 or newer, below 3 | dependency lookup |
| CMake | 3.24 or newer | configuring: Meson reads the CMake template for ~cpmdcConfigVersion.cmake~ and stops when ~cmake~ is missing; also the ~packaging~ consumer build, whose CMake leg is skipped when ~cmake~ is not installed |
| Python 3 | 3.10 or newer, below 4 | build helpers and tests |
| ASE, pytest, i-PI | ASE 3.23 or newer, below 4; pytest 7 or newer; i-PI 3.3 or newer, below 4 | the ~python-api~ and ~python-pytest~ tests |
| cmocka | 1.1.7 or newer, below 3 | ~-Dwith_tests=true~ |
| MPI with Fortran bindings, BLAS and LAPACK | OpenMPI 4.1 or newer, below 6; OpenBLAS 0.3.34 or newer, below 0.4 | ~-Dwith_cpmd=true~ |
| FFTW3 | 3.3.11 or newer, below 4; optional | linked when OpenCPMD was configured with FFTW3 |

CI runs those two tests on ASE 3.23.0 and on the newest ASE 3 release.
~bench/constant_cutoff_npt.py run~ needs ASE 3.27 for ~LangevinBAOAB~.
Its ~start~ command draws Maxwell-Boltzmann momenta with ~thermalize_momenta~ on
ASE 3.29 and with ~MaxwellBoltzmannDistribution~ on earlier releases.

The C Cap'n Proto runtime (~c-capnproto~) is vendored in ~subprojects/~.
Meson fetches three subprojects on the first ~meson setup~: the shared schema
(~potentials-schema~, pinned in ~subprojects/potentials-schema.wrap~),
~capnp-fortran~, and ~minimage~; ~-Dwith_readcon=true~ adds ~readcon-core~.
On a machine without network access, download them first where the network is
available:

#+begin_src bash
meson subprojects download
#+end_src

* Build the default library
Clone the repository and run the default suite:

#+begin_src bash
git clone https://github.com/OmniPotentRPC/cpmdc.git
cd cpmdc
pixi run test-stub
#+end_src

~test-stub~ configures ~build/~ with tests on, compiles, and runs the Meson
suite.
A healthy run reports no failures.
The same steps without Pixi:

#+begin_src bash
meson setup build -Dwith_tests=true
meson compile -C build
meson test -C build --print-errorlogs
#+end_src

The [[file:../reference/build-options.org][build reference]] lists every Meson
option, installed artifact, and Pixi task.

* Build against OpenCPMD
The OpenCPMD archive needs the patches in ~tools/~ and position-independent
code; the [[file:opencpmd-archive.org][archive how-to]] covers that build.
With the archive in place:

#+begin_src bash
export CPMD_ROOT=/path/to/opencpmd-build
meson setup build-cpmd \
  -Dwith_cpmd=true \
  -Dcpmd_root="$CPMD_ROOT" \
  -Dwith_tests=true
meson compile -C build-cpmd
export CPMDC_PSEUDO_DIR=/path/to/PP_LIBRARY
meson test -C build-cpmd --print-errorlogs
#+end_src

Configuration stops when
~$CPMD_ROOT/lib/libcpmd.a~ or ~$CPMD_ROOT/obj/timetag.o~ is missing.
The live tests run OpenCPMD, which reads the pseudopotentials from
~CPMDC_PSEUDO_DIR~ (see the [[file:../reference/environment.org][environment reference]]).

The link uses the MPI Fortran dependency, OpenBLAS (or LAPACK and BLAS when
OpenBLAS is absent), FFTW3 when found, ~libgfortran~, and ~libquadmath~.
When OpenCPMD was built with MPI compiler wrappers, configure with the same
wrappers so both sides agree on one MPI:

#+begin_src bash
CC=mpicc FC=mpif90 meson setup build-cpmd \
  -Dwith_cpmd=true -Dcpmd_root="$CPMD_ROOT"
#+end_src

* Install
#+begin_src bash
meson setup build-install --prefix "$HOME/.local" -Dwith_tests=false
meson install -C build-install
pkg-config --modversion cpmdc
#+end_src

The last command prints the project version, which Meson reads from
~version.txt~.
Hosts that load the library at run time, such as ~rgpot~, look for it through
~CPMDC_LIBRARY~; see the [[file:../reference/environment.org][environment reference]].

Installed shared libraries and plugins that need another library from the prefix
record a run path relative to their own file: ~$ORIGIN~ on Linux and
~@loader_path~ on macOS.
~libcpmdc~ sets an empty install run path, because it does not load another
library from the prefix; toolchain directories Meson already recorded, such as
the one for ~libgfortran~, stay.
~libcpmdc_gromacs~ records ~$ORIGIN~ (its own directory).
The LAMMPS plugin is installed one directory deeper, in
~lib/cpmdc~, and records ~$ORIGIN/..~.
~cpmdc-ipi-c~ records the normalised relative path from the resolved ~bindir~ to
the resolved ~libdir~.
~-Dbindir=.~, absolute ~bindir~ and ~libdir~ under the prefix, a nested
~libdir~, and a path that contains ~..~ or a trailing slash still open
~libcpmdc~.
A layout whose relative path cannot be stored as one run path entry fails at
configure time.
Meson keeps a build-tree run path only on uninstalled binaries.
After ~meson install~, an installed ~.so~ or ~.dylib~ does not point at the
build tree or at the prefix path used for that install, so the tree can be moved
and ~libcpmdc_gromacs~ still opens ~libcpmdc~.

The installed ~cpmdc.pc~, ~cpmdc-restart.pc~, ~cpmdc-damp.pc~, and ~libcp2k.pc~
files derive ~prefix~ and ~includedir~ from ~${pcfiledir}~, using the relative
path from the pkg-config directory to those locations.
~-Dlibdir=.~, a nested ~libdir~, a ~libdir~ that contains ~..~, and an absolute
~includedir~ under the prefix stay inside the prefix.
A directory that cannot be expressed as one relative path fails at configure
time.

* Install the Python package
Release tags publish wheels for Linux x86_64 and aarch64 (manylinux_2_28) and
macOS arm64 (macOS 15 or newer).
One wheel per platform serves CPython 3.10 and newer; CI tests 3.10 to 3.13.
The ~ase~ extra installs ASE for ~cpmdc.ase~:

#+begin_src bash
pip install "cpmdc[ase]"
python -c "import cpmdc; print(cpmdc.find_library())"
#+end_src

The second command prints the ~libcpmdc~ inside the installed package.
That library is the default build: the reference evaluator, without OpenCPMD and
without MPI, so ~Session.available()~ is false.
The wheel carries ~libgfortran~ and ~schema/Potentials.capnp~.
A periodic cell needs no other tool: the package encodes each step as
~ForceInput~ itself.
The ~capnp~ command is needed only to encode a ~CPMDParams~ text file, and
~cpmdc.find_schema()~ returns the schema to encode it against.
The ~test~ extra adds pytest for ~tests/python~.
To evaluate with OpenCPMD, build ~libcpmdc~ with
~-Dwith_cpmd=true~ and set ~CPMDC_LIBRARY~ to it; the variable takes precedence
over the copy in the wheel.

On other platforms pip builds the sdist.
That needs the C, C++, and Fortran compilers, Rust (~cargo~, for the ~minimage~
subproject), the ~capnp~ command, and network access for the Meson subprojects.
The same build from a checkout:

#+begin_src bash
pip install ".[ase]"
#+end_src
