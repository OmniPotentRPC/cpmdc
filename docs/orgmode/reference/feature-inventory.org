* Two copies of one list
~cpmdc~ keeps its capability list twice.
~src/cpmdc_features.c~ compiles it into the library, where
~cpmdc_feature_count()~, ~cpmdc_feature_table()~, and ~cpmdc_feature_find()~
serve it at run time.
~schema/inventory/cpmd_features.json~ holds the same rows with metadata for
the checks.
The Meson suite fails when the two copies, the schema, the headers, or the
docs drift apart.

* Feature IDs

| Namespace | Kind | Example | Means |
|-----------+------+---------+-------|
| ~abi.*~ | ~CPMDC_FEATURE_ABI~ | ~abi.cpmdc_session_calculate_result~ | an exported C function |
| ~params.*~ | ~CPMDC_FEATURE_PARAMS~ | ~params.cutOffRy~ | a top-level ~CPMDParams~ field |
| ~params.inputSections.<arm>.<field>~ | ~CPMDC_FEATURE_PARAMS~ | ~params.inputSections.cpmd.maxIter~ | a typed field inside a section arm |
| ~catalog.section.*~ | ~CPMDC_FEATURE_SECTION~ | ~catalog.section.PIMD~ | a deck section OpenCPMD's parser reads with ~inscan('&NAME')~ |
| ~catalog.cpmd.*~ | ~CPMDC_FEATURE_KEYWORD~ | ~catalog.cpmd.ODIIS~ | a ~&CPMD~ keyword or inline option spelling |
| ~catalog.dft.*~ | ~CPMDC_FEATURE_KEYWORD~ | ~catalog.dft.PCGC~ | a ~&DFT~ keyword |
| ~section.*~ | inventory only | ~section.generic~ | a ~CPMDInputSection~ union arm |

A ~params.*~ row names a field you can write.
A ~catalog.*~ row says that the renderer can emit a keyword or section,
often through a text field of a typed section rather than a field of its own.
~stub_applicable~ and ~embed_applicable~ say whether the stub build and the
OpenCPMD build expose the row.

* Query it from C
#+begin_src c
const CPMDCFeatureEntry *e = cpmdc_feature_find("params.inputSections.cpmd.odiisVectors");
if (e != NULL && e->embed_applicable) {
  /* this library renders ODIIS with a vector count */
}
for (size_t i = 0; i < cpmdc_feature_count(); ++i) {
  const CPMDCFeatureEntry *row = &cpmdc_feature_table()[i];
  /* row->feature_id, row->kind, row->stub_applicable, row->embed_applicable */
}
#+end_src

* The inventory file
Top-level keys of ~schema/inventory/cpmd_features.json~:

| Key | Holds |
|-----+-------|
| ~version~ | inventory format version |
| ~schema~ | the schema file it describes |
| ~opencpmd_reference~ | the OpenCPMD source it was probed against, as a description, never a local path |
| ~opencpmd_inscan_sections~, ~cpmd_sections~ | the 25 sections OpenCPMD parses with ~inscan~; the two lists must be equal |
| ~section_kinds~ | the ~CPMDSectionKind~ enum values with their ~section.*~ IDs |
| ~params_fields~ | the top-level ~CPMDParams~ fields |
| ~abi_symbols~ | every public ~cpmdc_*~ function |
| ~cpmd_keywords~, ~dft_keywords~, ~dft_functionals~ | keyword and functional catalogs |
| ~features~ | one object per row: ~feature_id~, ~kind~, ~name~, ~stub_applicable~, ~embed_applicable~, ~role~ |

Plain-text companions in ~schema/inventory/~: ~opencpmd_sections.txt~ (the
section allowlist), ~cpmd_cp_keywords.txt~ (base ~&CPMD~ keywords),
~dft_functionals.txt~, and ~surface_map_abi.txt~.

* The checks
All run in the default Meson suite; the ~inventory~ suite selects most of
them.

| Test | Fails when |
|------+------------|
| ~feature-inventory~ | the JSON inventory disagrees with ~schema/Potentials.capnp~, the C table, the public headers, the README, or the option docs; with ~CPMD_ROOT~ set, also when the live ~inscan~ probe finds a section the inventory lacks |
| ~cpmd-base-keyword-inventory~ | a base ~&CPMD~ keyword in ~cpmd_cp_keywords.txt~ has no ~catalog.cpmd.*~ row |
| ~cpmd-params-field-inventory~ | a top-level ~CPMDParams~ field has no ~params.*~ row, or the inventory or the C table has a duplicate |
| ~cpmd-public-abi-inventory~ | a public ~cpmdc_*~ function is missing from ~abi_symbols~, the table, or its implementation in ~src/cpmdc.c~, ~src/cpmdc_stub.c~, or ~src/cpmdc_features.c~ |
| ~stub-abi-symbol-coverage~ | the stub test does not assert every ~abi_symbols~ row |
| ~shared-dlopen-symbol-coverage~ | the ~dlopen~ test does not load every ~abi_symbols~ entry from ~libcpmdc.so~ |
| ~cpmd-schema-render-coverage~ | a typed ~CPMDCpmdSection~ field has no render mapping |
| ~cpmd-option-token-coverage~ | an inline option token in a fixture has no render coverage |
| ~cpmd-typed-render-field-coverage~ | a typed ~cpmd~, ~system~, ~dft~, or ~atoms~ field is absent from the render fixtures and assertions |
| ~cpmd-long-tail-section-coverage~ | a ~CPMDDirectiveSection~ arm is missing from the long-tail fixture, the render assertions, or the option reference |
| ~cpmd-escape-hatch-coverage~ | ~inputBlocks~, ~generic~, ~set~, or ~raw~ lose schema, fixture, render, or docs coverage |
| ~cpmd-inscan-token-fidelity~ | a typed ~render_*_section~ literal is not accepted by that section's readers in ~opencpmd_reader_tokens.json~, other than the ~P03 typed-carrier-fidelity~ carriers |
| ~opencpmd-reader-tokens~ | the extractor attributes a comment, a ~WRITE~ string, or another section's keyword to the wrong section |

Run them together:

#+begin_src bash
meson test -C build --suite inventory --print-errorlogs
#+end_src

To include the live probe, point ~CPMD_ROOT~ at an OpenCPMD source tree:

#+begin_src bash
CPMD_ROOT=/path/to/opencpmd meson test -C build feature-inventory -v
#+end_src

A passing live probe prints ~probed /path/to/opencpmd: 25 inscan sections~.
Without ~CPMD_ROOT~ the test prints a warning and skips that part.

* Reader token snapshot
~schema/inventory/opencpmd_reader_tokens.json~ holds the keyword literals
OpenCPMD ~062582b7cfd832d36f88f504cd08e4ead42eb404~ tests in each input
section.
For every section the extractor finds the procedure that calls
~inscan('&SECTION')~ and the readers that procedure calls.
Fortran comments are removed first.
A string counts only when ~keyword_contains~ or ~INDEX~ tests it on the
input line (~line~, ~previous_line~, or ~next_words~), or when
~index_of_delimiter~ tests that keyword.
A comment, a ~WRITE~, or a keyword that belongs to another section stays
out.
Delegated readers such as constraints and metadynamics collective
variables are nested under the section that calls them.
The file records ~extractor_version~ and ~opencpmd_sha~.

Refresh it from an OpenCPMD checkout:

#+begin_src bash
python3 tools/opencpmd_reader_tokens.py /path/to/OpenCPMD/CPMD \
  -o schema/inventory/opencpmd_reader_tokens.json
#+end_src

~cpmd-inscan-token-fidelity~ reads that snapshot.
It does not need an OpenCPMD tree.
Each literal a typed ~render_*_section~ writes is checked against that
section's readers.
~keyword_contains~ must match whole words, and an ~and~ companion is
required when the reader requires it.
~INDEX~ matches a prefix of a word (~REPL~ matches ~REPLICA~).
A line whose words are all literals that section tests is not reported.
The typed carriers the owning reader would not accept stay expected
failures with reason ~P03 typed-carrier-fidelity~:
~&VDW~ ~GRIMME~, ~S6~, ~RADIUS~;
~&RESP~ ~WEIGHT~, ~HYPERBOLIC~, ~BETA~;
~&EXTE~ ~EFIELD~;
~&VECTORS~ ~NEWORTHO~, ~OVERLAP~;
~&PATH~ ~SPRING~;
~&CPMD~ ~SHAKE~.
Nothing else is an expected failure.
~&TDDFT~ does not write ~CONVERGENCE~.
OpenCPMD 062582b tests that keyword in ~&LINRES~, and
~CPMDTddftSection.convergence~ stays on the struct.
Point ~OPENCPMD_READER_TREE~ at a checkout to rebuild the snapshot and
fail when it drifts:

#+begin_src bash
OPENCPMD_READER_TREE=/path/to/OpenCPMD/CPMD \
  meson test -C build cpmd-inscan-token-fidelity -v
#+end_src

~opencpmd-reader-tokens~ checks the extractor on a small tree:
~S6GRIMME~ is a ~&VDW~ literal, ~GRIMME~ is not, a keyword that exists
only in a comment is not collected, and a ~&CPMD~ keyword is not attributed
to ~&VECTORS~.

* Add a row
Adding a typed keyword touches the schema, the renderer, the C table, the
inventory file, and the option docs in one change; the [[file:../contributing/index.org][contributing guide]]
lists the files and the focused test command.
