#+TITLE: Wavefunction state between calls
#+OPTIONS: toc:nil todo:nil num:nil author:nil title:t

A force call on a geometry close to the previous one should not start its
self-consistent field (SCF) from scratch.
The converged orbitals of the last call, ~c0~ in OpenCPMD, are a far better
starting point than atomic orbitals, and keeping them in memory is the main
reason to run CPMD inside the host.
This page follows ~c0~ from call to call.

* Cold and warm calls
The process keeps the converged orbitals, the cell, and the method that produced
them.
Each session keeps a counter of its own successful calls.

| Call | Condition | What runs |
|------+-----------+-----------|
| cold | first call of the process, or a changed functional, deck, cell, cutoff, charge, multiplicity, atom count, or elemental composition | the full CPMD setup on the composed deck, then the SCF from CPMD's initial guess, or from ~RESTART~ when the deck has ~RESTART WAVEFUNCTION~ |
| warm | a previous success in this process kept the same functional, deck, cell, cutoff, charge, multiplicity, and elemental composition, including a new session or a reordering of those atomic numbers | new positions into ~tau0~, ~phfac~, then the SCF from the stored ~c0~ |
| in place | as warm, but a constant-cutoff deck under ~CPMDC_CELL_IN_PLACE~ whose new cell lies within the strain limit of the setup cell | the new cell on the setup's plane waves, then as warm |

A cell counts as unchanged when every component of ~ForceInput.box~ matches the
stored cell within 1e-8 Angstrom, and when both calls agree on having a box at
all.
A new session has no cell of its own yet, so that comparison uses the cell
stored with the orbitals.
The cutoff matches within 1e-8 Rydberg.
The elemental composition is the count of each atomic number.
Reordering the same atoms keeps that composition.
The charge and the multiplicity belong to the same match.
A failed warm call leaves the counter where it was, so the next call is warm
again; a failed cold call clears the stored results.
An SCF that does not converge does not replace the stored orbitals.
When ODIIS exhausts ~MAXITER~, the same call continues once with ~PCG MINIMIZE~.
That pass restores the previous converged ~c0~ when a converged copy is already
stored, and it still counts as warm.
When the continuation runs out too, the call fails, and the message in
~CPMDCResult.message~ and ~cpmdc_last_error()~ names the minimizer of each pass,
the iteration each one stopped at, ~MAXITER~, and the final ~gemax~ against
~CONVERGENCE ORBITALS~:
#+begin_example
CPMD SCF did not converge: PCG MINIMIZE stopped at iteration 2 of MAXITER 2 with gemax 1.107715E-02 above CONVERGENCE ORBITALS 1.000000E-05, after ODIIS stopped at iteration 2 of MAXITER 2
#+end_example
That is water with BLYP at 50 Ry under ~MAXITER 2~, the case
~tests/test_scf_unconverged.c~ runs against OpenCPMD.
A host that prints ~cpmdc~'s message, as rgpot's ~CPMD engine failed:~ does,
shows these fields unchanged.
A ~stopgm~ during the call is not that failure: the wavefunction, forces, and
module state of the call are undefined, ~cpmdc~ drops the stored orbitals and
the warm cell, and the next call runs setup again.
With more than one MPI rank, ~cpmdc~ aborts the other ranks.

* Where the orbitals are kept
~opencpmd_embed_rwfopt.patch~ adds a module-level copy of ~c0~ to
~rwfopt_utils~.
At the end of ~rwfopt~, every rank saves its own slice of ~c0~ when
~embed_warm_orbitals~ is true and ~ropt_mod%convwf~ is true.
A call that does not converge leaves the previous copy in place.
A failed store allocation calls ~stopgm~.
~cpmdc~ sets ~embed_warm_orbitals~ on every SCF, including the first.
Restore does nothing until a converged copy exists, so the first call still
starts from CPMD's guess and stores ~c0~ only if that SCF converges.
On a later call, ~rwfopt~ copies the saved ~c0~ in before ~initrun~.
~rinitwf~ then returns after the phase factors, so it does not build a guess,
and the density ~initrun~ builds comes from those orbitals.
A restart read inside ~initrun~ can replace ~c0~, so ~rwfopt~ copies the saved
orbitals in again after ~initrun~ when the shape still matches.
A different shape calls ~stopgm~ and names ~embed_reset_warm_orbitals~.
~cpmdc~ makes that call when the functional, the deck, the cutoff, the cell, the
charge, the multiplicity, the atom count, or the elemental composition changes,
before ~rwfopt~ runs; a cell that moves in place keeps the orbitals.
The SCF then runs to the orbital convergence threshold with the full ~MAXITER~
budget of the deck; a warm call is a complete SCF from a better start, not a
shortened one.

~opencpmd_converged_state.patch~ makes the saved copy trustworthy.
In stock OpenCPMD, ~updwf~ applies an optimiser step to ~c0~ before it checks
convergence, so the orbitals left behind after the last iteration have moved one
step past the ones that produced the reported energy and forces.
The patch checks convergence first and updates only unconverged orbitals, so the
saved ~c0~ is the state that ~forcedr~ used.
Steepest descent with ~iproj <= 1~ sets ~gemax~ above the threshold before that
check: those steps do not converge on ~gemax~.

* Orbitals per key
One calculator often evaluates several calculations in turn: the images of a
band on fewer calculators than images, or the beads of a ring polymer.
With one stored copy, each SCF starts from the orbitals of whichever calculation
ran last on that calculator, which for a ring is a neighbouring bead rather than
the same bead one step earlier.
~cpmdc_session_select_orbitals()~ names the calculation the next evaluations
belong to.
The call records the key, and the evaluation selects it.
A key named and then replaced before an evaluation parks nothing.
~opencpmd_embed_rwfopt.patch~ keeps a table of stored ~c0~ copies, one per key,
beside the store ~rwfopt~ restores from.
Selecting another key parks the ~c0~ of the key being left, including a stale
copy from an unconverged pass, and moves the copy parked under the new key
into the store.
A partial copy from an unconverged pass is not parked.
~cpmdc_session_copy_orbitals()~ duplicates one key's converged orbitals, and
the geometry they converged at, into another key, replacing that key's
previous copy.
The selected key stays selected.
When the destination is the selected key, its live store is replaced
immediately.
A key with no converged orbitals is refused.
A donor whose last pass did not converge is refused as well, whether that
copy is the live store or a parked slot, and a copy onto the same key is
refused too.
Selecting that key again, or a warm start that adopts the parked slot, keeps
the refusal.
Every rank of a calculator names the same keys.
Every rank of a calculator selects the same key, and each rank parks its own
slice of ~c0~.
~CPMDC_ORBITAL_SLOT_LIMIT~ bounds how many inactive keys stay parked beside the
active store: when a new key needs a parked slot at the limit, the oldest
parked copy is evicted, while the active store and any key being selected are
kept; leaving it unset retains every parked key.
A basis change frees the table with the store, since every copy in it has the
shape of the old basis.
A session that never selects a key keeps one stored copy.

* Distance limit
Every stored and parked ~c0~ carries the geometry it converged at, the Angstrom
positions the caller passed.
Before each SCF, ~embed_choose_warm_start_metric_v2~ measures the
root-mean-square distance per atom from the new geometry to each of them,
without alignment.
The nearest one starts the SCF.
It is either the store, which holds the selected key's own copy or, when that
key has none, the copy of the key last left, or another key's parked copy, which
is copied so the donor keeps its own.
When that distance exceeds ~CPMDC_WARM_RMSD~ (default 0.15 Angstrom), the SCF
starts from the deck's guess instead, and the stored copy of that call is
dropped.
A negative limit starts from the store at any distance.
When the native ~tclust~ flag is false, the metric uses minimage's Euclidean
closest lattice image in the native cell, including skew cells.
A true ~tclust~ flag selects absolute Cartesian distances even when a cell is
supplied.
The parser sets this flag for ~CLUSTER~, ~SURFACE~, ~POLYMER~ or ~SYMMETRY 0~; a
~POISSON~ keyword alone does not establish it.
Coordinates are compared in species order without rotation or alignment.
A cell or boundary-model change invalidates every stored orbital state,
including when the distance limit is negative.
A cell that moves in place is not such a change: the distances then use the
setup cell, the cell of the plane waves the orbitals are written on.

The default comes from the Si3N4 BLYP 70 Ry band (7 atoms, 14 Angstrom cell,
ODIIS, 4 ranks per calculation).
One process makes two calls.
The second sits a set distance along the band from the first and starts from the
first call's orbitals or from the deck's atomic guess.
Five starting images, means over them per call:

A band step capped at 0.1 Angstrom per atom stays inside the limit, so an image
that returns to its own key is warm.
~CPMDC_SCF_STEPS=1~ prints the start of every call.

* Extrapolation between calls
A warm start is a zeroth-order guess: the next SCF starts from the last
converged orbitals as they are.
Along a trajectory with equal time steps, a combination of the orbitals of the
earlier steps predicts the next ones better.
Car-Parrinello molecular dynamics (CPMD) does this in its own Born-Oppenheimer
molecular dynamics (BO-MD) with ~EXTRAPOLATE WFN~, and the always stable
predictor-corrector (ASPC) of Kolafa (J. Comput. Chem. 25, 335 (2004),
doi:10.1002/jcc.10385) is one of its coefficient sets. CP2K extrapolates by default, with ASPC of order 3 (~FORCE_EVAL/DFT/QS EXTRAPOLATION~), and Quantum ESPRESSO offers first- and second-order extrapolation of the wavefunctions after Arias, Payne, and Joannopoulos (Phys. Rev. B 45, 1538 (1992), doi:10.1103/PhysRevB.45.1538).

OpenCPMD turns the keyword off in a wavefunction optimisation, which is the job
a host-driven call runs.
~tools/opencpmd_embed_extrapolate.patch~ keeps the request and lets ~rwfopt~ act
on it when the orbitals stay in memory.
After a converged SCF, the orbitals go into the store as before.
At the start of the next call, ~rwfopt~ pushes that copy into a ring of ~order~
entries and calls CPMD's ~extrapwf~, which builds the prediction, rotates the
earlier sets onto the newest one by their overlap, and orthonormalises the
result.
The SCF then runs from that prediction to the same convergence threshold.
The ring is one per process, not one per key, so a key change, an unconverged
pass, or a start past the distance limit empties it.
An unconverged pass empties it even when a converged copy was already stored.
~opencpmd_embed_rwfopt.patch~ marks that copy stale on that branch, and
~opencpmd_embed_extrapolate.patch~ calls ~embed_break_history~ there.
Before those hunks, that pass left the ring in place, and only a first
unconverged pass, the one that keeps a partial copy, cleared it.
The [[file:../howto/extrapolate-orbitals.org][extrapolation how-to]] lists those
events.

A water molecule with the Becke-Lee-Yang-Parr (BLYP) functional at 50 Ry, on one
rank, makes the comparison.
~cpmd.x~ ran the deck of ~tests/water_aspc_params.capnp.txt~ as BO-MD for 40
steps of 10 atomic time units.
The library route ran the same 41 geometries from ~cpmd.x~'s trajectory, one
call each, in one process.
SCF iterations count steps 1 to 40; the first SCF, cold on both routes, took 18.

* Cell changes at a constant cutoff
A plane wave is a reciprocal lattice vector G(m) = 2 pi m H^-1 for integer m and
lattice rows H, so the set of m inside the cutoff sphere, and with it the layout
of ~c0~, belongs to the cell of the setup.
The penalty of ~CONSTANT CUTOFF~ leaves the components above E0 + 2 sigma
empty in any cell.
While the setup's set of m holds every m whose G in the new cell lies below
E0 + 2 sigma, the setup's plane waves span every occupied component of the new
cell, and the stored orbitals still fit.
With T = H_setup^-1 H_new, the squared length of G(m) in the setup cell is at
most the largest eigenvalue of T T^T times its length in the new cell, so
~cpmdc~ asks that this eigenvalue times E0 + 2 sigma stay within the
wavefunction cutoff, and four times as much within the density cutoff.

~CPMDC_CELL_IN_PLACE~ turns the move on and bounds the principal strain from
the setup cell, the largest stretch or shrink of a length.
A cell within it goes into ~metr_com%ht~, and OpenCPMD's ~newcell~ rescales the
G vectors, the structure factors, and the pseudopotential tables, as OpenCPMD's
own variable-cell dynamics does each step.
The SCF then starts from the stored orbitals and the ~EXTRAPOLATE WFN~ history.
The move also asks for the Gamma point, norm-conserving pseudopotentials, a
periodic deck, the lattice class of the setup (a cube that stays a cube, an
orthorhombic cell, or ~CELL VECTORS~), and the same method otherwise.
A cell past the limit, or one that fails a condition, sets CPMD up again, and
the strain is measured from that new setup cell.

The plane waves between E0 + 2 sigma and the cutoff are then those of the setup
cell rather than of the new one, which moves the energy and the stress away
from those of a new setup in proportion to the strain.
On 32 waters at a 100 Ry cutoff with E0 = 85 Ry and sigma = 4.25 Ry, a 1%
stretch in place differs from a new setup by 3.3 meV in the energy, 0.08
meV/Angstrom in the forces, and 32 bar in the pressure.
The tail of erf reaches further below E0 at a wider sigma: the one-water deck
at 40 Ry with E0 = 30 Ry and the default sigma of 3 Ry differs by about 3 meV,
1.5 meV/Angstrom, and 3e-6 eV/Angstrom^3 for the same stretch.
Within one setup, the energies of the moved cells lie on one smooth surface
whose derivative is the stress, which the ~python-pytest~ case
~test_the_constant_cutoff_stress_is_the_volume_derivative_of_the_energy~ checks.

* What clears the orbitals

| Event | Why |
|-------+-----|
| a cell change, unless it moves in place | the plane-wave basis depends on the cell, so the stored coefficients no longer fit |
| a cutoff change | the plane-wave basis changes, so the stored coefficients no longer fit |
| a change of atom count or elemental composition, or of charge or multiplicity | those inputs set the number of states, and a restored ~c0~ of another shape calls ~stopgm~ |
| ~cpmdc_session_set_params()~ or ~cpmdc_session_configure()~ when the functional, cutoff, charge, multiplicity, or deck differs | the next evaluation drops the orbitals; the call itself keeps them |
| a new session with the same functional, deck, cutoff, cell, charge, multiplicity, and elemental composition | reuses the stored orbitals and skips setup |
| a new session whose functional, deck, cutoff, cell, charge, multiplicity, or elemental composition differs | the next evaluation drops the stored orbitals and runs setup |
| a one-shot or global call (~cpmdc_set_params()~, ~cpmdc_energy*()~, ~cpmdc_calculate_result()~) whose basis differs from the stored one | that call runs setup; a matching basis reuses the orbitals |
| ~stopgm~ returns through ~cpmd_stopgm_hook~ | the call continued past a failed check, so the stored orbitals are not a result |

A topology change is refused outright rather than treated as cold: the atom
count and the elemental composition belong to the session.
A reordering of those atomic numbers stays on the session.
A new session with that composition keeps the stored orbitals.
An evaluation whose positions match the previous successful call on that
session, including that reordering, returns the stored energy and forces.

An evaluation that needs a second setup, for a basis that differs from the first
or after a ~stopgm~, tears the first one down in the same process.
The teardown frees the module arrays, communicators, and first-call state of
that setup (~embed_teardown_state~ from ~tools/opencpmd_embed_teardown.patch~),
and the new setup gives the energies of a fresh process.
Resetting the embed after a failed call tears down the same way.
~tistart~ runs once per process: OpenCPMD executes ~STOP~ on a second call.

* The RESTART file
A library force call writes no ~RESTART.1~, ~LATEST~, ~GEOMETRY~, or
~GEOMETRY.xyz~.
The orbitals for the next call stay in memory.
~cpmd.x~ writes those files.
A cold library call reads a ~RESTART.1~ only when the deck asks for
~RESTART WAVEFUNCTION~.
~cpmdc~ turns off CPMD's restart of coordinates, velocities, and the stored
geometry before every SCF.
The host owns the geometry, and a ~RESTART COORDINATES~ in the deck would
otherwise overwrite the step's positions.

To seed a cold start from an earlier run with a new geometry, patch the
positions of a ~RESTART.1~ with ~cpmdc-restart patch-positions~.
It rewrites only the coordinate records and copies the wavefunction records
unchanged; the deck then needs ~RESTART WAVEFUNCTION~.

~cpmdc-restart~ and ~cpmdc_restart_write_path()~ replace a ~RESTART~ file in
one step, so a ~cpmd.x~ or a library call that opens it at the same time reads
the previous file or the finished one, never part of the new one.
The image goes to a short-named temporary file next to the effective
destination. A new destination is opened with mode 0666 under the umask as a
plain ~fopen~ would; replacement keeps the destination's existing mode.
On POSIX, when ~RESTART~ is a symbolic link, as in CPMD's
~RESTART -> RESTART.1~ convention, the target is replaced and the link
survives. A dangling link, whose target is not there yet, is resolved hop
by hop to the end of the chain, even past the first missing name, and the
real end is created there: a relative target at each hop is taken from the
directory that holds that hop's link, and the new file takes mode 0666
under the umask, as ~fopen~ did. While it walks, the writer holds an
~O_DIRECTORY~ descriptor for the parent of the destination and one for the
directory that contained each symlink it followed, and it records that
symlink's device, inode, and target text. Immediately before ~renameat~ it
reads those descriptors again with ~fstatat~ and ~AT_SYMLINK_NOFOLLOW~. If
any followed symlink is no longer that same link, or the final component
is no longer the absent name or the same file that was resolved, the write
fails, the temporary file is removed, and nothing is renamed. A loop, or a
link that cannot be read, is left in place and the write fails.

That check and the rename are not one operation. POSIX has no call that
renames a file only when a whole symlink chain is unchanged, so a full
guarantee is not available. The ~renameat~ uses the directory descriptor
taken during resolution, which pins that directory inode: replacing an
earlier path component afterwards does not redirect the write onto the
replacement. On Linux, when the headers and kernel provide ~renameat2~ with
~RENAME_NOREPLACE~, an absent final name that appears in the gap is left
alone and the write fails. If that operation is unavailable or rejected,
the writer falls back to plain ~renameat~; a name that appears in the gap
can then be overwritten. When the resolved destination is an existing
file, the last check and the ~renameat~ are also two calls, and a
substitution of that directory entry in the gap can be overwritten.
Windows resolves none of this: the destination is written as given, with
no symlink handling at all.
The writer flushes that file and syncs it with ~fsync~, renames it over the
destination, and syncs the directory with ~fsync~, so the new name also
survives a crash.
On Windows, ~_commit~ flushes the file and ~MoveFileEx~ with
~MOVEFILE_REPLACE_EXISTING~ and ~MOVEFILE_WRITE_THROUGH~ replaces the
destination.
A failure before the rename removes the temporary file and leaves the old
~RESTART~ in place.
A directory that cannot be synced is reported as a failure even though the new
file is already in place; a filesystem that cannot sync a directory at all
(~EINVAL~) is not.
Only a crash before the rename leaves a ~.tmp.~ file behind, and it can be
deleted.

* The optimiser on a warm start
A warm start changes how far the SCF has to go, not how it gets there.
CPMD's optimiser choice then decides the cost: ODIIS reuses its history of
residuals, while ~PCG MINIMIZE~ runs a line minimisation per step.
On the Si3N4 cluster of the [[file:routes.org][route comparison]], the same
minimisation took 515 SCF steps at 1.26 s with ~PCG MINIMIZE~ and 296 steps at
0.64 s with ODIIS, to the same minimum.
