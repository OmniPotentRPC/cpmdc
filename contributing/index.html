Contributing¶

Bug reports, fixes, tests, documentation, and new typed keywords for the input deck are welcome. Report a problem or propose a change on the GitHub issue tracker. Send the change itself as a pull request to the cpmdc repository on GitHub. The sections below list the checks to run first and the files that each kind of change touches.

Development Checks¶

Run the default parser, socket, and stub checks before changing the ABI, schema, renderer, or session runtime:

meson setup build -Dwith_tests=true
meson compile -C build
meson test -C build --print-errorlogs

Use focused suites while iterating, then run the default suite before pushing a public change:

Params render coverage lives under tests/cmocka/ and uses cmocka assertions on generated Cap’n Proto types (read_CPMDParams, deck substrings) only. Session tests use encoded CPMDParams and ForceInput fixtures from tests/*.capnp.txt. feature-inventory ties the generated JSON inventory to the schema, public feature table, docs, public headers, ABI symbol list, and optional CPMD_ROOT parser section probe. cpmd-base-keyword-inventory requires every base &CPMD keyword in schema/inventory/cpmd_cp_keywords.txt to resolve to a catalog.cpmd.* row. cpmd-params-field-inventory requires every top-level CPMDParams schema field to resolve to a params.* feature row and rejects duplicate inventory IDs/lists and C feature table duplicates before set comparisons can hide them. cpmd-public-abi-inventory requires every public cpmdc_* header function to resolve through abi_symbols and the feature table, then verifies the native src/cpmdc.c, stub src/cpmdc_stub.c, or shared src/cpmdc_features.c implementation that exports it. stub-abi-symbol-coverage requires the standalone stub test to assert every abi_symbols feature row is present and stub-applicable. shared-dlopen-symbol-coverage requires the shared-library dlopen test to load every abi_symbols entry from libcpmdc.so. cpmd-schema-render-coverage and cpmd-option-token-coverage keep typed CPMDCpmdSection fields and fixture inline tokens tied to render coverage. cpmd-typed-render-field-coverage requires typed cpmd, system, dft, and atoms fields to appear in render fixtures or render assertions. cpmd-long-tail-section-coverage requires every CPMDDirectiveSection union arm to appear in the long-tail fixture, render assertions, and option reference. cpmd-escape-hatch-coverage requires inputBlocks, generic, set, and raw carriers to stay covered by schema, fixtures, render tests, and option docs. cpmd-embedding-docs-coverage requires the embedding how-to to name the public ABI feature IDs plus the typed, long-tail, and escape-hatch CPMDParams carrier IDs used by host authors. cpmd-public-header-docs-coverage requires the public header and generated C API docs to describe the serialized CPMDParams input surface. examples-documented requires public docs to point at the runnable examples/host_step.c host program. readme-navigation keeps the README and build-and-test how-to focused on entry paths, work-loop labels, and current wording. reference-contract requires every function, type, enum constant, and macro of cpmdc.h, cpmdc_features.h, and cpmdc_restart.h in the C ABI reference, each function with its parameter list in a table row, an __all__ in every python/cpmdc module that lists its public functions and classes, each of those names and each public member of an exported class in the Python reference, and no cpmdc_ name in the README or the Org pages that no public header declares. docs-examples classifies every code block of the README and the Org pages. It runs the blocks the default build can run, compiles the C fragments against include/, and lists the rest in tests/test_docs_examples.py: blocks that need OpenCPMD in OPENCPMD, whose surrounding text must say so, and the others in SKIP with the tool or input they need. Every shell block, run or not, must name meson options, pixi tasks, meson tests and suites, repository paths, and build outputs that exist. A new block fails the test until it is classified.

NumPy preflight¶

tests/python/conftest.py multiplies small matrices with @ and with a loop before collecting any test (tests/python/blas_probe.py), and stops the session with exit status 3 when they differ by more than 1e-12 of the scale of the product. The references of the GROMACS and ASE tests use @, which NumPy gives to OpenBLAS, and OpenBLAS chooses its kernel from the CPU it detects. Under qemu-user 8.2 with -cpu max on aarch64 the detected core is armv9sme, and 195 of 385 product shapes then come out wrong, with one OpenBLAS thread, by the size of the result, so a NumPy reference sums nothing and every comparison with the library fails far from the cause; whether the emulation of SME or the kernel is at fault was not settled. On such a machine set OPENBLAS_CORETYPE to an older core, ARMV8 on aarch64, or run the emulator with QEMU_CPU=max,sme=off.

GROMACS tests¶

tests/python/test_gromacs.py runs under Meson’s python-pytest. Without GROMACS it still checks the library through ctypes:

  • the unit factors against GROMACS’ units.h;

  • the energy and forces of the whole system against CPMDCCalculator to 1e-10, in a cubic and a triclinic box;

  • unwrapping across the boundary, and the whole QM region with CELL NONE;

  • the mechanical embedding against an independent NumPy Ewald sum in a cubic and a triclinic box, its convergence with the precision, a finite difference of its forces, and the direct sum without a box; both sides sum the same terms, so the energy agrees to 1e-12 Ha and a force element to 1e-12 Ha plus 1e-10 relative, against a rounding bound of 6e-16 Ha and measured differences of at most 4e-17 Ha on x86-64 and aarch64; the splitting parameters rcut and alpha that the shim logs agree to 1e-14 relative, against the 1.5e-15 that the two determinants of the box leave;

  • the stress of cp2k_get_stress_tensor(), as ASE’s stress: with CELL PERIODIC against CPMDCCalculator to 1e-13 and ASE’s central difference under a 1e-6 strain of the cell to 1e-8 of its largest element; with CELL NONE, with and without the mechanical embedding, against the same difference of the library’s own energy; each in a cubic and a triclinic box, and the box of GROMACS 2026 read the same as that of 2024;

  • no stress without a box or for an isolated periodic deck;

  • the error for each refused input.

With gmx_d from CPMDC_GMX or on PATH, it also runs grompp and mdrun:

  • one step of two QM waters, the whole system, in a cubic and a triclinic box: Quantum En. against CPMDCCalculator to 1e-10 relative and equal to Potential, and the forces to 1e-10 relative, read with gmx energy -dp and from the double-precision .trr;

  • one QM water among three MM waters with PME: Quantum En. and the QM atom forces against the reference evaluator plus the NumPy Ewald sum;

  • 2000 NVE steps of each system: the total energy stays within 2e-3 and 5e-3 of the swing of the potential energy;

  • the virial and pressure of step 0 from rest with md-vv, two QM waters in a cubic and a triclinic box: Vir equals 0.5 V sigma of CPMDCCalculator’s ASE stress to 1e-9 relative, and Pres equals -sigma;

  • one QM water among three MM waters with PME, in a cubic and a triclinic box: each element of Vir equals half the central difference of Potential under a 1e-5 strain of the box and positions, to 1e-8 of its largest element, so the QM, QM-MM, and classical terms all enter it;

  • generated input, EMBEDDING ELECTROSTATIC, and charged MM atoms without an embedding each stop mdrun with the reason.

With gmx_mpi_d from CPMDC_GMX_MPI, a double-precision GROMACS built with -DGMX_MPI=ON, launched by CPMDC_MPIEXEC (default mpiexec):

  • 20 NVE steps of 64 waters in a 2.4 nm box, one of them QM with its atoms across the periodic boundary in x and y, on 2 and 4 ranks with QM_RANKS ALL and on 4 with QM_RANKS 1: Quantum En., Potential and Total Energy of every step and the positions and forces of steps 0, 10 and 20 match the one-rank run to 1e-10, and the virial and pressure of every step to 1e-9 of their largest element, so the QM virial enters once. The pair list is rebuilt every step without a buffer (nstlist = 1, verlet-buffer-tolerance = -1), so that every decomposition sees the same pairs;

  • -npme 1 stops mdrun with GROMACS’ refusal of separate PME ranks.

tests/test_installed_pkgconfig_consumer.py builds a libcp2k client from an installed libcp2k.pc alone and runs it without LD_LIBRARY_PATH. After the prefix is moved it rejects an installed shared library or executable whose run path points at the build tree or the original prefix, then runs the pkg-config, libcp2k, and CMake consumers from that tree. cpmdc-ipi-c is run the same way, without the prefix on LD_LIBRARY_PATH.

The CI job gromacs-qmmm builds GROMACS 2025.5 three ways and fails if any of its tests skips:

Route

GROMACS

Tests

build

thread-MPI, against build/tools/gromacs

the one-rank tests and the Meson suite

installed

thread-MPI, against the libcp2k.pc of meson install into build/prefix

the same, with libcpmdc and libcpmdc_gromacs from the prefix

The reference evaluator of a build without OpenCPMD is a well about the origin. Two consequences show in the tests: the mdp sets comm-mode = None, because removing the centre-of-mass motion of a system with a net external force takes energy out of NVE, and the QM/MM NVE run gives the QM hydrogens a small Lennard-Jones repulsion, because the well does not bind them to their oxygen. An OpenCPMD energy needs neither.

LAMMPS tests¶

tests/python/test_lammps.py runs both routes under Meson’s python-pytest and checks:

  • energy, forces, and virial against CPMDCCalculator to 1e-10, in a cubic and a triclinic box and without a cell, under metal, real, and electron;

  • each of the six virial components against a central difference of the energy under strain on the triclinic box;

  • the type-to-element map, unwrapping across the boundary, and press against the virial trace;

  • energy drift of a short NVE run and of the extended energy of an NPT run;

  • the error for each refused input and a failed step;

  • two ranks against one, under mpiexec.

The module skips with a reason when the lammps module cannot start, and the plugin cases skip when cpmdcplugin.so is not built. The reference evaluator of a build without OpenCPMD is a harmonic well about the origin, which is not translation invariant; NPT runs on it need fixedpoint 0 0 0, which an OpenCPMD energy does not.

Add a typed CPMD keyword¶

Use a typed field when a CPMD control has stable structure, affects ordinary host inputs, or should be discoverable through cpmdc_feature_find(). Use directives, set, generic, raw, or inputBlocks for rare literal deck fragments that should stay text.

Start from the test surface:

File

Required change

tests/test_params_cp_dft_render.c

Add catalog coverage and rendered-token checks

tests/test_features_cmocka.c

Add catalog.cpmd.* and params.inputSections.cpmd.* expectations

tests/params_*.capnp.txt

Add a fixture value that exercises the new field

Run the focused failure before adding production code:

CPMD_ROOT=OpenCPMD-cpmdc meson test -C build \
  params-cp-dft-render features-cmocka feature-inventory \
  cpmd-base-keyword-inventory cpmd-params-field-inventory \
  cpmd-public-abi-inventory cpmd-schema-render-coverage \
  stub-abi-symbol-coverage \
  shared-dlopen-symbol-coverage \
  cpmd-option-token-coverage cpmd-typed-render-field-coverage \
  cpmd-long-tail-section-coverage \
  cpmd-escape-hatch-coverage \
  --print-errorlogs

Then update the production and docs surface in one change:

File

Required change

schema/Potentials.capnp

Add the CPMDCpmdSection field with the next field number

src/cpmdc_params.c

Render the exact &CPMD deck spelling accepted by OpenCPMD

src/cpmdc_features.c

Add catalog and parameter feature table rows

schema/inventory/cpmd_features.json

Add matching inventory metadata

schema/inventory/cpmd_cp_keywords.txt

Re-run the focused command, then run:

meson test -C build --print-errorlogs
pixi run -e docs sphinxbld

For parser coverage audits, compare OpenCPMD control_utils.mod.F90 keyword_contains(line, ...) branches against catalog.cpmd.* rows. Treat context-specific branch tokens as covered by their structured parent when the schema field renders the accepted deck form, such as LBFGS_NTRUST for LBFGS NTRUST or NOSE_IONS_LOCAL for NOSE IONS LOCAL.

Documentation¶

Documentation source lives under docs/orgmode (authoritative prose), with light/dark logos in docs/source/_static/ and branding/logo/. Build docs (exports Org to RST, Doxygen XML, Sphinx HTML with Antics analytics):

pixi run -e docs docbld

Link between pages with Org file links, [[file:../howto/mpi.org][text]]. The default export is ox-rst. A file link whose target ends in .org becomes a Sphinx :doc: role, so the same link works on the forge and in the built site. Set CPMDC_ORG_EXPORT=pandoc to export with pandoc instead. That path applies docs/org-links.lua and makes the same :doc: rewrite. Generated docs/source/**/*.rst is not committed.

When a page moves, leave a short page at the old path that starts with an :orphan: export block and links to the new page, as docs/orgmode/tutorials/quickstart.org does. The old address then keeps working, and readme-navigation does not ask the README to link that page.

Regenerate RST after editing Org sources:

pixi run -e docs mkrst

Regenerate the LLM index files (llms.txt and llms-full.txt) after editing docs/orgmode/ or schema/inventory/cpmd_features.json:

python3 scripts/generate_llms_txt.py

The generator writes deterministic output without timestamps or host paths. Verify that committed index files match the sources with python3 scripts/generate_llms_txt.py --check or meson test -C build llms-txt --print-errorlogs; when a file is stale or missing, the check names the file, prints the regeneration command above, and shows a short unified diff head.

Check the links in the README, the Org sources, and the newsfragments:

pixi run -e docs lychee

The task runs lychee 0.24.2 from the docs Pixi environment with .lychee.toml, which also checks the anchor of a link such as README.md#citation. A link to a file on the main branch fails until that file lands there.

The Sphinx theme injects antics-api.turtletech.us/antics.js via docs/source/_templates/partials/extra-head.html, and the footer credit lives in docs/source/_templates/partials/site-foot.html (same pattern as rgpot).
